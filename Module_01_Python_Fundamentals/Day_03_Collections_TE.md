## 1. సాఫ్ట్‌వేర్ రంగంలో కలెక్షన్స్ ఎందుకు అవసరం? (The "Why")

కంపెనీలలో రియల్ టైమ్ ప్రాజెక్టులు చేసేటప్పుడు మనం కేవలం ఒకే ఒక వాల్యూతో పనిచేయం. సమూహాలుగా ఉండే డేటాతో డీల్ చేస్తాం:
- బ్యాంక్ లావాదేవీల జాబితా: `[120.5, 45.0, 990.0]` → **List (లిస్ట్)**
- సర్వర్ ఉండే ఫిక్స్‌డ్ లొకేషన్ కోఆర్డినేట్స్: `(17.3850, 78.4867)` → **Tuple (టపుల్)**
- మన వెబ్‌సైట్‌కి వచ్చిన ప్రత్యేక విజిటర్ల IP అడ్రస్‌లు (డూప్లికేట్లు లేకుండా): `{"192.168.1.1", "10.0.0.5"}` → **Set (సెట్)**
- ఒక ఉద్యోగి పూర్తి సమాచారం (కీ-వాల్యూ జతలు): `{"name": "రవి", "role": "AI ఇంజనీర్"}` → **Dictionary (డిక్షనరీ)**

సరియైన డేటా స్ట్రక్చర్ ఎంచుకోకపోతే మీ సాఫ్ట్‌వేర్ వేల రెట్లు స్లో అయిపోతుంది!

## 2. నాలుగు కలెక్షన్ల మధ్య పోలిక (Comparison Table)

| కలెక్షన్ | సింటాక్స్ | ఆర్డర్ ఉంటుందా? | ఇండెక్స్ ద్వారా వెతకొచ్చా? | మార్చవచ్చా? (Mutable) | డూప్లికేట్ విలువలు ఒప్పుకుంటుందా? | ఎప్పుడు వాడాలి? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **List** | `[1, 2, 3]` | ✅ అవును | ✅ అవును (`[0]`) | ✅ అవును (Mutable) | ✅ అవును | తరచూ మారే డేటా జాబితా కోసం |
| **Tuple** | `(1, 2, 3)` | ✅ అవును | ✅ అవును (`[0]`) | ❌ మార్చలేము (Immutable) | ✅ అవును | ఎప్పటికీ మారకూడని రికార్డులు (Coordinates) |
| **Set** | `{1, 2, 3}` | ❌ ఉండదు | ❌ ఉండదు | ✅ అవును | ❌ డూప్లికేట్స్ తీసేస్తుంది | డూప్లికేట్స్ తొలగించడానికి, సూపర్ ఫాస్ట్ సెర్చ్ |
| **Dictionary** | `{"a": 1}` | ✅ అవును | 🔑 కీ (Key) ద్వారా | ✅ అవును | ❌ కీలు డూప్లికేట్ కాకూడదు | JSON డేటా, ఫాస్ట్ సెర్చ్ టేబుల్స్ కోసం |

## 3. ప్రాక్టికల్ విశ్లేషణ (Practical Deep Dive)

### A. లిస్ట్‌లు & స్లైసింగ్ (Lists & Slicing)
లిస్ట్‌లు ఆర్డర్‌గా ఉంటాయి మరియు వాటిలో ఏ డేటా టైప్‌నైనా పెట్టుకోవచ్చు.

```python
tech_stack = ["Python", "FastAPI", "Docker", "PyTorch", "Kubernetes"]

# ఇండెక్సింగ్: మొదటిది 0 తో మొదలవుతుంది. నెగటివ్ ఇండెక్స్ వెనుక నుండి వస్తుంది
print(tech_stack[0])   # 'Python'
print(tech_stack[-1])  # 'Kubernetes' (చివరి ఐటమ్)

# స్లైసింగ్: list[start : stop : step] (చివరి stop నెంబర్ తీసుకోదు!)
print(tech_stack[1:4])   # ['FastAPI', 'Docker', 'PyTorch']
print(tech_stack[::-1])  # మొత్తం లిస్ట్‌ని రివర్స్ చేస్తుంది!

# ముఖ్యమైన లిస్ట్ మెథడ్స్
tech_stack.append("LangChain")       # చివర్లో కొత్త ఐటమ్ యాడ్ చేస్తుంది
tech_stack.insert(1, "PostgreSQL")   # ఇండెక్స్ 1 వద్ద చేరుస్తుంది
tech_stack.pop()                     # చివరి ఐటమ్‌ని తీసేస్తుంది
print("అప్‌డేట్ చేసిన లిస్ట్:", tech_stack)
```

### B. టపుల్స్ (Tuples - మారకూడనివి)
టపుల్‌ను ఒకసారి తయారు చేశాక అందులో కొత్తవి చేర్చలేము, మార్చలేము.

```python
# సర్వర్ లొకేషన్ (అక్షాంశం, రేఖాంశం)
server_location = (17.3850, 78.4867)

# ❌ మార్చడానికి ప్రయత్నిస్తే ఎర్రర్ వస్తుంది:
# server_location[0] = 18.0000  # TypeError వస్తుంది!

# టపుల్ అన్‌ప్యాకింగ్ (విలువలను విడివిడిగా తీసుకోవడం)
lat, lon = server_location
print(f"అక్షాంశం (Latitude): {lat}, రేఖాంశం (Longitude): {lon}")
```

### C. సెట్‌లు (Sets - డూప్లికేట్లు ఉండనివి)
సెట్‌లో ఒకే విలువ మళ్లీ మళ్లీ ఉండదు. అంతేకాదు, ఇందులో ఏదైనా వెతకడం సెకనులో లక్షో వంతు సమయం ($O(1)$) లోనే జరుగుతుంది.

```python
# డూప్లికేట్ యూజర్ ఐడీలతో కూడిన రా డేటా
raw_user_ids = [101, 102, 103, 101, 104, 102, 105]

# కేవలం ఒకే ఒక్క లైన్‌లో డూప్లికేట్స్ తొలగించడం:
unique_users = set(raw_user_ids)
print("ప్రత్యేక యూజర్లు:", unique_users)  # {101, 102, 103, 104, 105}

# గణిత ఆపరేషన్లు (యూనియన్, ఇంటర్‌సెక్ట్)
team_a_skills = {"Python", "SQL", "Docker"}
team_b_skills = {"Docker", "Kubernetes", "AWS"}

print("ఉమ్మడి నైపుణ్యాలు (Intersection):", team_a_skills & team_b_skills)  # {'Docker'}
print("అన్ని నైపుణ్యాలు (Union):", team_a_skills | team_b_skills)
print("కేవలం Team A కి మాత్రమే ఉన్నవి:", team_a_skills - team_b_skills)   # {'Python', 'SQL'}
```

### D. డిక్షనరీలు (Dictionaries - కీ & వాల్యూ జతలు)
మొత్తం ఇంటర్నెట్ అంతా JSON ఫార్మాట్‌లో నడుస్తుంది. ఆ JSON ఫార్మాట్ పైథాన్‌లో డిక్షనరీయే!

```python
employee = {
    "emp_id": "EMP-9021",
    "name": "పూజా రెడ్డి",
    "designation": "AI ఇంజనీర్",
    "skills": ["Python", "Transformers", "GCP"],
    "is_active": True
}

# .get() ద్వారా విలువను సేఫ్‌గా తీసుకోవడం (కీ లేకపోతే ప్రోగ్రామ్ క్రాష్ అవ్వదు)
print(employee["name"])                        # 'పూజా రెడ్డి'
print(employee.get("salary", "వెల్లడించలేదు"))  # కీ లేకపోయినా డీఫాల్ట్ వాల్యూ ఇస్తుంది

# కొత్త కీ యాడ్ చేయడం లేదా మార్చడం
employee["salary"] = 850000
employee["designation"] = "సీనియర్ AI ఇంజనీర్"

# లూప్ ద్వారా డిక్షనరీ చూడటం
for key, value in employee.items():
    print(f"{key:15} -> {value}")
```

## 4. కాంప్రెహెన్షన్స్ (Comprehensions)

పెద్ద పెద్ద `for` లూప్‌లు రాయకుండా ఒకే లైన్‌లో కోడ్ రాయడానికి కాంప్రెహెన్షన్స్ వాడతాం:

```python
# పాత పద్ధతి:
squares = []
for n in range(1, 6):
    squares.append(n ** 2)

# ✅ లేటెస్ట్ పైథానిక్ లిస్ట్ కాంప్రెహెన్షన్:
even_squares = [n ** 2 for n in range(1, 11) if n % 2 == 0]
print("సరి సంఖ్యల వర్గాలు:", even_squares)  # [4, 16, 36, 64, 100]

# ✅ డిక్షనరీ కాంప్రెహెన్షన్ (డాలర్ల నుండి రూపాయల్లోకి మార్చడం):
products = ["ల్యాప్‌టాప్", "మౌస్", "కీబోర్డ్"]
prices_usd = [1000, 25, 75]
USD_TO_INR = 83.0

inr_prices = {item: price * USD_TO_INR for item, price in zip(products, prices_usd)}
print("రూపాయల్లో వస్తువుల ధరలు:", inr_prices)
```

## 5. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **లూప్ నడుస్తున్నప్పుడే లిస్ట్‌లోని ఐటమ్స్ డిలీట్ చేయడం:** 
   - `for x in my_list: my_list.remove(x)` అని రాస్తే ఇండెక్స్‌లు మారిపోయి కొన్ని ఐటమ్స్ స్కిప్ అవుతాయి. లిస్ట్ కాపీ మీద రన్ చేయాలి.
2. **డిక్షనరీ కీ లేనప్పుడు డైరెక్ట్‌గా యాక్సెస్ చేయడం:**
   - `data["missing"]` అంటే `KeyError` వచ్చి ప్రోగ్రామ్ ఆగిపోతుంది. ఎల్లప్పుడూ `data.get("missing", default)` వాడటం మంచిది.
3. **ఖాళీ సెట్ అనుకుని ఖాళీ డిక్షనరీ రాయడం:**
   - `x = {}` రాస్తే అది ఖాళీ డిక్షనరీ అవుతుంది కానీ ఖాళీ సెట్ అవ్వదు! ఖాళీ సెట్ కోసం `x = set()` రాయాలి.

## 6. ప్రాక్టీస్ ల్యాబ్ (Daily Hands-On Lab)

### 🧪 టాస్క్: ఈ-కామర్స్ ఆర్డర్ల విశ్లేషణ ప్రోగ్రామ్
**సన్నివేశం:** మీ వద్ద కొన్ని కస్టమర్ ఆర్డర్ల వివరాలు ఉన్నాయి. అందులో ప్రత్యేక కస్టమర్లను గుర్తించి, కేటగిరీల వారీగా వచ్చిన ఆదాయాన్ని లెక్కించి, ₹2000 పైబడిన ప్రీమియం ఆర్డర్లను వేరు చేయాలి.

```python
# ==========================================
# Day 3 Lab: ఈ-కామర్స్ డేటా అనలైజర్
# ==========================================

orders = [
    {"order_id": 1001, "customer": "అనన్య", "item": "మెకానికల్ కీబోర్డ్", "category": "Electronics", "price": 4500},
    {"order_id": 1002, "customer": "రవి",   "item": "కాఫీ మగ్",          "category": "Home",        "price": 450},
    {"order_id": 1003, "customer": "అనన్య", "item": "వైర్‌లెస్ మౌస్",      "category": "Electronics", "price": 1200},
    {"order_id": 1004, "customer": "కిరణ్",  "item": "పైథాన్ AI బుక్",     "category": "Books",       "price": 850},
    {"order_id": 1005, "customer": "రవి",   "item": "ఆఫీస్ కుర్చీ",       "category": "Furniture",   "price": 12500},
]

# 1. సెట్ (Set) ఉపయోగించి ప్రత్యేక కస్టమర్లను కనుగొనడం:
unique_customers = {order["customer"] for order in orders}
print(f"1. మొత్తం ప్రత్యేక కస్టమర్లు ({len(unique_customers)}): {unique_customers}")

# 2. డిక్షనరీ ద్వారా ప్రతి కేటగిరీకి వచ్చిన మొత్తం సేల్స్ లెక్కించడం:
category_revenue = {}
for order in orders:
    cat = order["category"]
    category_revenue[cat] = category_revenue.get(cat, 0) + order["price"]

print("\n2. కేటగిరీల వారీగా ఆదాయం:")
for cat, rev in category_revenue.items():
    print(f"   - {cat:15}: ₹{rev:,.2f}")

# 3. లిస్ట్ కాంప్రెహెన్షన్ ద్వారా ప్రీమియం ఆర్డర్లు (>= ₹2,000) వేరు చేయడం:
premium_orders = [
    f"{order['item']} - కొన్నవారు: {order['customer']} (ధర: ₹{order['price']})"
    for order in orders
    if order["price"] >= 2000
]
print("\n3. ₹2,000 పైబడిన ప్రీమియం ఆర్డర్లు:")
for p in premium_orders:
    print(f"   ★ {p}")
```

## 7. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: లిస్ట్‌కి మరియు టపుల్‌కి మధ్య ప్రధాన తేడా ఏమిటి?**
   - **సమాధానం:** లిస్ట్ అనేది మ్యూటబుల్ (Mutable - ఐటమ్స్ యాడ్ చేయవచ్చు, మార్చవచ్చు, తొలగించవచ్చు) మరియు `[]` వాడతారు. టపుల్ అనేది ఇమ్మ్యూటబుల్ (Immutable - మార్చలేము) మరియు `()` వాడతారు. టపుల్స్ చాలా వేగంగా పనిచేస్తాయి మరియు తక్కువ మెమొరీ తీసుకుంటాయి.
2. **ప్రశ్న: లిస్ట్ కంటే సెట్ లేదా డిక్షనరీలో డేటాను వెతకడం ఎందుకు వేగంగా జరుగుతుంది?**
   - **సమాధానం:** సెట్ మరియు డిక్షనరీలు అంతర్గతంగా **హాష్ టేబుల్స్ (Hash Tables)** టెక్నాలజీని ఉపయోగిస్తాయి. కాబట్టి వాటిలో వెతకడానికి సగటున $O(1)$ సమయం మాత్రమే పడుతుంది. లిస్ట్‌లో అయితే మొదటి నుండి వెతుక్కుంటూ వెళ్లాలి కాబట్టి $O(n)$ సమయం పడుతుంది.
3. **ప్రశ్న: ఒక లిస్ట్‌ని డిక్షనరీ కీ (Key) గా ఉపయోగించవచ్చా?**
   - **సమాధానం:** ఉపయోగించలేము! ఎందుకంటే డిక్షనరీ కీలు తప్పనిసరిగా ఇమ్మ్యూటబుల్ (Immutable) మరియు హాషబుల్ (Hashable) అయి ఉండాలి (ఉదాహరణకి Strings, Numbers లేదా Tuples మాత్రమే కీలుగా పనికొస్తాయి).
