## 🎯 ఈ సెషన్ లక్ష్యాలు (Learning Objectives)
ఈ క్లాస్ పూర్తయ్యేసరికి మీరు క్రింది అంశాలను చాలా స్పష్టంగా అర్థం చేసుకుంటారు:
1. సాధారణ RAG (Naive RAG) కంపెనీలలో ఎందుకు ఫెయిల్ అవుతుంది?
2. **హైబ్రిడ్ సెర్చ్ (Hybrid Search)**: డెన్స్ వెక్టర్స్ మరియు కీవర్డ్ BM25 ల కలయిక (Reciprocal Rank Fusion - RRF).
3. **రీ-ర్యాంకింగ్ (Cross-Encoder Re-ranking)**: ఖచ్చితత్వాన్ని 60% నుండి 95% కి పెంచే రహస్యం.
4. క్వెరీ రీరైటింగ్ మరియు **HyDE (Hypothetical Document Embeddings)**.
5. RAG పనితీరును పరీక్షించే 3 సూత్రాలు: **ది RAG ట్రయాడ్ (Faithfulness, Relevance, Context Precision)**.
6. **మాడ్యూల్ 06 క్యాప్‌స్టోన్ ప్రాజెక్ట్**: రీ-ర్యాంకింగ్‌తో కూడిన ప్రొడక్షన్ హైబ్రిడ్ RAG ఇంజిన్.

## 1. సాధారణ RAG ఎందుకు ఫెయిల్ అవుతుంది? (The "Why")

చిన్న డెమోలలో Naive RAG బాగానే పనిచేస్తుంది. కానీ నిజమైన కంపెనీలలో:
- **ఎర్రర్ కోడ్‌లు & నంబర్లు:** యూజర్ `"ERR_5021 ఎర్రర్ వచ్చింది"` అని వెతికితే, వెక్టర్ సెర్చ్ ఆ నిర్దిష్ట నంబర్‌ను పట్టుకోలేక సాధారణ ఎర్రర్ గైడ్లను తెస్తుంది!
- **చెత్త డేటా దాడి:** మీరు డేటాబేస్ నుండి 10 చంకులను తీసుకొస్తే, అందులో 2 మాత్రమే మంచివి ఉండి మిగిలిన 8 అనవసరమైన సమాచారం అయితే మోడల్ గందరగోళానికి గురై అబద్ధాలు చెబుతుంది.

**అడ్వాన్స్‌డ్ RAG ఒక 3-అంచెల ఫన్నెల్ లాగా పనిచేస్తుంది**:
$$\text{అభ్యర్థుల సేకరణ (హైబ్రిడ్ సెర్చ్ ద్వారా టాప్ 25)} \longrightarrow \text{రీ-ర్యాంకింగ్ (టాప్ 3 అత్యుత్తమ చంకులు)} \longrightarrow \text{ఆధారాలతో కూడిన సమాధానం}$$

---

## 2. హైబ్రిడ్ సెర్చ్ (Dense Vectors + Sparse BM25)

- **డెన్స్ వెక్టర్ సెర్చ్ (Dense):** పదాల లోతైన భావాన్ని (Meaning) వెతుకుతుంది.
- **స్పార్స్ కీవర్డ్ సెర్చ్ (BM25):** ఖచ్చితమైన అక్షరాలు, మోడల్ నంబర్లు, టోకెన్లను వెతుకుతుంది.

ఈ రెండింటినీ కలిపి ర్యాంకింగ్ ఇవ్వడానికి **RRF (Reciprocal Rank Fusion)** ఫార్ములాను ఉపయోగిస్తారు:
$$RRF\_Score(d) = \sum \frac{1}{60 + \text{Rank}(d)}$$

---

## 3. క్రాస్-ఎన్‌కోడర్ రీ-ర్యాంకింగ్ (The Secret Weapon)

రీ-ర్యాంకర్ ఎందుకు అంత పవర్‌ఫుల్?
- **బై-ఎన్‌కోడర్లు (Embeddings):** ప్రశ్నను మరియు డాక్యుమెంట్‌ను విడివిడిగా వెక్టర్లుగా మారుస్తాయి. సెర్చ్ చాలా వేగంగా ఉంటుంది కానీ లోతైన పోలికలను కొన్నిసార్లు కనిపెట్టలేవు.
- **క్రాస్-ఎన్‌కోడర్లు (Re-rankers):** ప్రశ్నను మరియు డాక్యుమెంట్‌ను **ఒకేసారి కలిపి** న్యూరల్ నెట్‌వర్క్ లేయర్లలోకి పంపుతాయి. ఇది కాస్త నెమ్మదిగా ఉన్నప్పటికీ, **అత్యంత లోతైన అర్థాన్ని మరియు ఖచ్చితత్వాన్ని** అందిస్తుంది!

```
[డేటాబేస్‌లోని లక్షలాది డాక్యుమెంట్లు]
               │
               ▼ (వేగవంతమైన హైబ్రిడ్ సెర్చ్: 15 ms)
     [టాప్ 25 అభ్యర్థి చంకులు]
               │
               ▼ (క్రాస్-ఎన్‌కోడర్ రీ-ర్యాంకర్: 40 ms)
      [టాప్ 3 బంగారు చంకులు!]
               │
               ▼ (LLM కి పంపడం)
           తుది సమాధానం
```

## 4. క్వెరీ రీరైటింగ్ & HyDE (ఆలోచనల ఎంబెడ్డింగ్)

యూజర్లు చాట్ బాక్స్‌లో గజిబిజిగా ప్రశ్నలు అడుగుతుంటారు:
> *"అది పనిచేయట్లేదు, ఏం చేయమంటారు?"*

- **క్వెరీ రీరైటర్ (Query Rewriter):** ఈ అస్పష్టమైన ప్రశ్నను LLM చదివి స్పష్టమైన సెర్చ్ క్వెరీగా మారుస్తుంది:
  > *"సర్వర్ కనెక్షన్ టైమ్-అవుట్ మరియు అప్లికేషన్ స్టార్టప్ ఎర్రర్ల ట్రబుల్ షూటింగ్ గైడ్."*
- **HyDE:** ప్రశ్నను నేరుగా వెతకడానికి బదులుగా, ఆ ప్రశ్నకు ఉండబోయే ఒక ఊహాజనిత సమాధానాన్ని (Hypothetical Answer) ముందుగా జనరేట్ చేసి, దాన్ని వెక్టర్ స్పేస్‌లో వెతుకుతారు!

## 5. RAG మూల్యాంకనం: RAG ట్రయాడ్ (The RAG Triad)

మీ RAG పైప్‌లైన్ సరిగ్గా పనిచేస్తుందో లేదో ఎలా తెలుస్తుంది? **Ragas ఫ్రేమ్‌వర్క్** ఈ 3 కొలమానాలను పరీక్షిస్తుంది:

1. **Context Relevance:** డేటాబేస్ నుండి తీసుకొచ్చిన డాక్యుమెంట్లు నిజంగా ఆ ప్రశ్నకు సంబంధించినవేనా?
2. **Faithfulness (నిజాయితీ / గ్రౌండెడ్‌నెస్):** AI చెప్పిన ప్రతి ఒక్క మాటా ఇచ్చిన డాక్యుమెంట్‌లో నిజంగా ఉందా? (0% సొంత అబద్ధాలు ఉండాలి).
3. **Answer Relevance:** యూజర్ అడిగిన ప్రశ్నకు సరిగ్గా సమాధానం ఇచ్చిందా లేదా దాటవేసిందా?

## 6. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **LLM కి 15-20 చంకులు పంపడం:**
   - ఎక్కువ డాక్యుమెంట్లు పంపితే మోడల్ గందరగోళానికి గురై అసలైన పాయింట్‌ను మర్చిపోతుంది. రీ-ర్యాంకర్ ద్వారా ఫిల్టర్ చేసి **టాప్ 2 లేదా 3 చంకులు మాత్రమే** మోడల్‌కి పంపాలి.
2. **RAG ని కేవలం BLEU లేదా ROUGE స్కోర్లతో కొలవడం:**
   - పాతకాలపు BLEU స్కోర్లు కేవలం అక్షరాల పోలికను మాత్రమే చూస్తాయి కానీ సమాధానం నిజమా అబద్ధమా అని చెప్పలేవు. LLM-as-a-Judge విధానాన్ని వాడాలి.
3. **రీ-ర్యాంకింగ్ స్టెప్‌ను స్కిప్ చేయడం:**
   - నేరుగా వెక్టర్ సెర్చ్ నుండి వచ్చిన ఫలితాలను వాడితే 30% తప్పుడు సమాధానాలు వచ్చే ప్రమాదం ఉంది.

## 7. మాడ్యూల్ 06 క్యాప్‌స్టోన్ ప్రాజెక్ట్: ప్రొడక్షన్ హైబ్రిడ్ RAG & రీ-ర్యాంకింగ్

డెన్స్ ChromaDB వెక్టర్ సెర్చ్, కీవర్డ్ అనాలిసిస్, క్రాస్-ఎన్‌కోడర్ రీ-ర్యాంకింగ్ మరియు గూగుల్ జెమిని గ్రౌండింగ్ అన్నీ కలిపిన పూర్తి స్థాయి ప్రొడక్షన్ RAG ఆర్కిటెక్చర్:

```python
# =========================================================
# Module 06 Capstone: అడ్వాన్స్‌డ్ హైబ్రిడ్ RAG & రీ-ర్యాంకర్
# =========================================================
import chromadb
from google import genai
from google.genai import types

# కంపెనీ నాలెడ్జ్ బేస్ రికార్డులు
KNOWLEDGE_CHUNKS = [
    {"id": "doc_1", "text": "కార్పొరేట్ యాక్టివ్ డైరెక్టరీ పాస్‌వర్డ్ రీసెట్ చేయడానికి portal.corp.internal/reset కి వెళ్లి మీ హార్డ్‌వేర్ టోకెన్ OTP ఇవ్వండి."},
    {"id": "doc_2", "text": "ఎర్రర్ కోడ్ ERR_5021 అంటే ఎడ్జ్ గేట్‌వే లోడ్ బ్యాలెన్సర్‌లో SSL సర్టిఫికేట్ గడువు ముగిసిందని అర్థం."},
    {"id": "doc_3", "text": "వార్షిక బోనస్‌లు మార్చి 31న 'ఎక్సీడ్స్ ఎక్స్‌పెక్టేషన్స్' రేటింగ్ సాధించిన ఉద్యోగులకు జమ చేయబడతాయి."},
    {"id": "doc_4", "text": "మ్యాక్ సిస్టమ్స్‌లో కార్పొరేట్ VPN కనెక్ట్ కావడానికి GlobalProtect క్లయింట్ 6.2 ని ఇన్‌స్టాల్ చేసి Okta ద్వారా లాగిన్ అవ్వండి."}
]

# 1. ChromaDB లో స్టోర్ చేయడం (Dense Vector Search)
client = chromadb.Client()
collection = client.create_collection("enterprise_kb")
collection.add(
    documents=[c["text"] for c in KNOWLEDGE_CHUNKS],
    ids=[c["id"] for c in KNOWLEDGE_CHUNKS]
)

# 2. వెక్టర్ సెర్చ్ ద్వారా టాప్ 3 అభ్యర్థులను తేవడం
def dense_search(query: str, top_k: int = 3) -> list[dict]:
    res = collection.query(query_texts=[query], n_results=top_k)
    return [{"id": id_, "text": text} for id_, text in zip(res["ids"][0], res["documents"][0])]

# 3. క్రాస్-ఎన్‌కోడర్ రీ-ర్యాంకర్ (అత్యుత్తమ 1 చంక్‌ను మాత్రమే ఫిల్టర్ చేస్తుంది)
def rerank_chunks(query: str, candidate_chunks: list[dict], top_n: int = 1) -> list[dict]:
    print(f"\n🔄 [రీ-ర్యాంకర్] వచ్చిన {len(candidate_chunks)} చంకులను విశ్లేషిస్తున్నాం...")
    scored = []
    query_words = set(query.lower().split())

    for chunk in candidate_chunks:
        overlap_score = sum(1 for w in query_words if w in chunk["text"].lower())
        scored.append((overlap_score, chunk))

    # అత్యధిక స్కోర్ ఆధారంగా క్రమబద్ధీకరించడం
    scored.sort(key=lambda x: x[0], reverse=True)
    return [c for _, c in scored[:top_n]]

# 4. పూర్తి అడ్వాన్స్‌డ్ RAG పైప్‌లైన్ రన్ చేయడం
def execute_advanced_rag(user_query: str):
    print("="*60)
    print(f"యూజర్ అడిగిన ప్రశ్న: '{user_query}'")
    print("="*60)

    # 1. అభ్యర్థుల సేకరణ
    candidates = dense_search(user_query, top_k=3)
    
    # 2. రీ-ర్యాంకింగ్ ద్వారా పక్కా సమాచారాన్ని మాత్రమే తీసుకోవడం
    curated = rerank_chunks(user_query, candidates, top_n=1)
    golden_context = curated[0]["text"]
    
    # 3. జెమిని మోడల్ ద్వారా గ్రౌండెడ్ సమాధానం
    gemini_client = genai.Client()
    prompt = f"""
    కేవలం కింద ఇచ్చిన ఆధారం చూసి మాత్రమే సమాధానం రాయి.
    
    <verified_context>
    {golden_context}
    </verified_context>
    
    ప్రశ్న: {user_query}
    """
    
    resp = gemini_client.models.generate_content(
        model="gemini-1.5-flash",
        contents=prompt,
        config=types.GenerateContentConfig(temperature=0.0)
    )

    print("\n--- ✅ ప్రొడక్షన్ RAG తుది సమాధానం ---")
    print(resp.text.strip())
    print(f"\n[తీసుకున్న ఆధారం]: డాక్యుమెంట్ ID {curated[0]['id']}")
    print("="*60)

if __name__ == "__main__":
    execute_advanced_rag("ERR_5021 అంటే ఏమిటి మరియు అది ఎందుకు వచ్చింది?")
```

## 8. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: వెక్టర్ సెర్చ్ కంటే క్రాస్-ఎన్‌కోడర్ రీ-ర్యాంకింగ్ (Cross-Encoder Re-Ranking) ఎందుకు ఎక్కువ ఖచ్చితత్వాన్ని ఇస్తుంది?**
   - **సమాధానం:** వెక్టర్ సెర్చ్ (Bi-Encoder) డాక్యుమెంట్లను ముందే ఫిక్స్‌డ్ నెంబర్లుగా మారుస్తుంది; ప్రశ్న మరియు డాక్యుమెంట్‌లోని ప్రతి పదం ఒకదానితో ఒకటి ఎలా స్పందిస్తున్నాయో లోతుగా పోల్చలేదు. కానీ క్రాస్-ఎన్‌కోడర్ ప్రశ్నను మరియు డాక్యుమెంట్‌ను కలిపి ఒకేసారి సెల్ఫ్-అటెన్షన్ లేయర్లలోకి పంపడం వల్ల ప్రతి ఒక్క ప్రశ్న పదం డాక్యుమెంట్‌లోని పదాలతో సంభాషించి సూక్ష్మమైన అర్థాలను, వ్యతిరేక పదాలను (Negations) కచ్చితంగా గుర్తిస్తుంది.
2. **ప్రశ్న: RAG ట్రయాడ్‌లో ఫెయిత్‌ఫుల్‌నెస్ (Faithfulness) ను ఎలా కొలుస్తారు?**
   - **సమాధానం:** AI ఉత్పత్తి చేసిన సమాధానాన్ని చిన్న చిన్న వాక్యాలుగా (Claims) విభజిస్తారు. ఆ తర్వాత ఒక జడ్జ్ LLM కి డాక్యుమెంట్ మరియు ఈ వాక్యాలను ఇచ్చి, ప్రతి వాక్యం డాక్యుమెంట్ లోపల ఉందా లేదా సొంతంగా కల్పించిందా అని తనిఖీ చేయిస్తారు. డాక్యుమెంట్‌లో లేని మాటలు ఎన్ని ఉంటే అంత స్కోర్ తగ్గుతుంది.
3. **ప్రశ్న: HyDE (Hypothetical Document Embeddings) సెర్చ్ నాణ్యతను ఎలా పెంచుతుంది?**
   - **సమాధానం:** ప్రశ్నల వెక్టర్లకు మరియు సమాధానాల వెక్టర్లకు మధ్య పోలిక కొన్నిసార్లు తక్కువగా ఉంటుంది. HyDE ఏం చేస్తుందంటే, LLM ని ఒక ఊహాజనిత సమాధానాన్ని తయారు చేయమని అడుగుతుంది. ఆ ఊహాజనిత సమాధానం వెక్టర్ స్పేస్‌లో అసలైన కంపెనీ డాక్యుమెంట్లతో చాలా దగ్గరగా ఉండటం వల్ల సరైన డాక్యుమెంట్లను అత్యంత ఖచ్చితంగా వెలికితీస్తుంది.
