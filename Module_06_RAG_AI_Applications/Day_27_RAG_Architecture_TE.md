## 1. ఓపెన్-బుక్ ఎగ్జామ్ ఉదాహరణ (The "Why")

ఒక క్లిష్టమైన మెడికల్ పరీక్ష జరుగుతోందని ఊహించుకోండి:
- **RAG లేని సాధారణ LLM (క్లోజ్డ్-బుక్ పరీక్ష):** విద్యార్థి పుస్తకాలు చూడకూడదు, కేవలం గతంలో బట్టీ పట్టిన జ్ఞానంతోనే రాయాలి. ఒకవేళ నిన్న రాత్రి ప్రభుత్వం కొత్త మెడికల్ రూల్ విడుదల చేస్తే, విద్యార్థికి తెలియక సొంతంగా కథలు అల్లేస్తాడు (Hallucination)!
- **RAG తో కూడిన LLM (ఓపెన్-బుక్ పరీక్ష):** విద్యార్థిని ప్రశ్న అడగ్గానే, ఒక లైబ్రేరియన్ వెంటనే పరిగెత్తుకుంటూ లైబ్రరీకి వెళ్లి **ఖచ్చితంగా ఆ ప్రశ్నకు సంబంధించిన 3 పేజీలను మాత్రమే** తెచ్చి విద్యార్థి చేతిలో పెడతాడు: *"ఈ 3 పేజీలు చూసి మాత్రమే సమాధానం రాయి, ఏ పేజీలో ఉందో కూడా మెన్షన్ చెయ్యి!"* అని చెబుతాడు.

విద్యార్థి మొత్తం లైబ్రరీని కంఠస్థం చేయాల్సిన పనిలేదు; ఎదురుగా ఉన్న పేజీలను చదివి సరైన సమాధానం రాస్తే చాలు!

## 2. RAG లోని 7 దశలు (The 7-Step Pipeline)

```
ఆఫ్‌లైన్ డాక్యుమెంట్ ప్రాసెసింగ్:
[కంపెనీ ఒరిజినల్ ఫైల్స్ (PDF, Word, HTML)]
               │
               ▼ (స్టెప్ 1: Document Loader)
          [టెక్స్ట్ సేకరణ]
               │
               ▼ (స్టెప్ 2: Chunking)
      [చిన్న చిన్న చంకులు (ముక్కలు)]
               │
               ▼ (స్టెప్ 3: Embedding Model)
       [సంఖ్యా వెక్టర్లుగా మార్చడం]
               │
               ▼ (స్టెప్ 4: Vector Database)
     [(ChromaDB లేదా Pinecone లో సేవ్ చేయడం)]

ఆన్‌లైన్ క్వెరీ సమయం:
          యూజర్ ప్రశ్న ("సెలవుల పాలసీ ఏమిటి?")
               │
               ▼ (స్టెప్ 5: Semantic Retrieval)
[వెక్టర్ డేటాబేస్ నుండి అత్యంత సరిపోలిన 2 లేదా 3 చంకులు తేవడం]
               │
               ▼ (స్టెప్ 6: Context Augmentation)
   ఆ సమాచారాన్ని కలిపి ప్రాంప్ట్ తయారు చేయడం
               │
               ▼ (స్టెప్ 7: LLM Generation)
  ఆధారాలతో కూడిన 100% నిజమైన సమాధానం!
```

## 3. చంకింగ్ వ్యూహాలు (Chunk Size & Overlap)

ఒక 50 పేజీల PDF ని ఒకే వెక్టర్‌గా మార్చవచ్చా?
- మార్చకూడదు! ఎందుకంటే 50 పేజీల సమాచారాన్ని ఒకే నంబర్‌గా మారిస్తే లోపల ఉన్న నిర్దిష్టమైన చిన్న చిన్న విషయాలు కలిసిపోయి అస్పష్టంగా మారిపోతాయి.
- అందుకే డాక్యుమెంట్‌ను 500 నుండి 800 అక్షరాల చిన్న **చంకులుగా (Chunks)** విడదీస్తాం.

### చంక్ ఓవర్‌ల్యాప్ (Chunk Overlap) ఎందుకు అవసరం?
ఒకవేళ ఒక ముఖ్యమైన వాక్యం సరిగ్గా రెండు చంకుల మధ్యలో తెగిపోతే:
- 1వ చంక్: *"...కంపెనీ ఉద్యోగుల వార్షిక బోనస్ ఎప్పుడు ఇస్తారంటే..."*
- 2వ చంక్: *"...కంపెనీ తన లాభాల టార్గెట్‌ను చేరుకున్నప్పుడు మాత్రమే."*

ఇప్పుడు రెండు ముక్కల్లోనూ పూర్తి నిజం లేదు!
**చంక్ ఓవర్‌ల్యాప్ (ఉదాహరణకి 50 అక్షరాలు)** ఏం చేస్తుందంటే, 1వ చంక్ చివర ఉన్న వాక్యాన్ని 2వ చంక్ ప్రారంభంలో మళ్లీ రిపీట్ చేస్తుంది. దీనివల్ల వాక్యాలు తెగిపోకుండా భావం స్థిరంగా ఉంటుంది.

```python
def naive_chunk_with_overlap(text: str, chunk_size: int = 200, overlap: int = 50) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end].strip()
        if chunk:
            chunks.append(chunk)
        start += (chunk_size - overlap)  # కిటికిని కొద్దిగా ముందుకు జరుపుతాం
    return chunks
```

## 4. గ్రౌండింగ్ & ప్రాంప్ట్ నిర్మాణం (Grounding Prompt)

RAG విజయవంతం కావడానికి ప్రాంప్ట్ నిర్మాణం చాలా కీలకం:

```python
GROUNDED_RAG_PROMPT_TEMPLATE = """
నువ్వు కంపెనీ అసిస్టెంట్‌వి. కింద <context> లో ఇచ్చిన సమాచారం ఆధారంగా మాత్రమే ప్రశ్నకు సమాధానం ఇవ్వు.

<rules>

2. నీ సొంత ఊహలు, అబద్ధాలు అస్సలు రాయవద్దు.

<context>
{తీసుకొచ్చిన_డాక్యుమెంట్_ముక్కలు}
</context>

<user_question>
{యూజర్_అడిగిన_ప్రశ్న}
```

## 5. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **చంకులు చాలా చిన్నగా లేదా చాలా పెద్దగా చేయడం:**
   - చాలా చిన్నది (50 అక్షరాలు): వాక్యం అర్థం మారిపోతుంది.
   - చాలా పెద్దది (5000 అక్షరాలు): అసలైన సమాధానం అనవసరపు పదాల మధ్య దాగిపోతుంది.
   - *ఉత్తమ సైజు*: 500 నుండి 800 అక్షరాలు, 10% ఓవర్‌ల్యాప్‌తో.
2. **వెక్టర్ డేటాబేస్ ఏమీ ఇవ్వకపోయినా LLM కి పంపడం:**
   - డేటాబేస్‌లో సంబంధం లేని సమాచారం వచ్చినప్పుడు దాన్ని ఫిల్టర్ చేయకుండా మోడల్‌కి పంపితే అది కచ్చితంగా అబద్ధాలు చెబుతుంది.
3. **ఆధారాలు (Citations) చూపించకపోవడం:**
   - యూజర్‌కి సమాధానం చెప్పినప్పుడు అది ఏ పేజీ నంబర్ లేదా ఏ పాలసీ డాక్యుమెంట్ నుండి వచ్చిందో చూపించాలి.

## 6. ప్రాక్టీస్ ల్యాబ్ (Daily Hands-On Lab)

### 🧪 టాస్క్: కంపెనీ పాలసీ RAG పైప్‌లైన్ (ChromaDB + Gemini)
**సన్నివేశం:** మీ ఆఫీస్ ఎంప్లాయ్ హ్యాండ్‌బుక్‌ని ChromaDB లో స్టోర్ చేసి, యూజర్ అడిగే ప్రశ్నలకు జెమిని మోడల్ ఆధారాలతో కూడిన నిజమైన సమాధానాలు ఇచ్చేలా RAG పైప్‌లైన్ నిర్మించండి.

```python
# =========================================================
# Day 27 Lab: ఎండ్-టు-ఎండ్ RAG పైప్‌లైన్
# =========================================================
import chromadb
from google import genai
from google.genai import types

# 1. కంపెనీ పాలసీ టెక్స్ట్
COMPANY_POLICY_DOC = """
టీచిన్ గ్లోబల్ ఎంప్లాయ్ హ్యాండ్‌బుక్ (2026 ఎడిషన్)
విభాగం 1: ల్యాప్‌టాప్ & హోమ్ ఆఫీస్ అలవెన్స్
ప్రతి ఉద్యోగికి ఇంటి వద్ద ఆఫీస్ సెటప్ కోసం ₹1,50,000 అలవెన్స్ ఇవ్వబడుతుంది. 
ప్రతి 24 నెలలకు ఒకసారి హార్డ్‌వేర్ అప్‌గ్రేడ్ చేసుకోవచ్చు.

విభాగం 2: ఆరోగ్యం మరియు వెల్‌నెస్ ప్రయోజనాలు
పూర్తి స్థాయి ఉద్యోగుల కుటుంబానికి ₹10,00,000 వరకు హెల్త్ ఇన్సూరెన్స్ వర్తిస్తుంది. 
అదనంగా మానసిక ఆరోగ్యం మరియు కౌన్సిలింగ్ కోసం సంవత్సరానికి ₹25,000 వెల్‌నెస్ స్టైపెండ్ లభిస్తుంది.

విభాగం 3: పేరెంటల్ లీవ్ (సంతాన సెలవులు)
తల్లులకు 26 వారాల పూర్తి జీతంతో కూడిన సెలవులు లభిస్తాయి. 
తండ్రులకు 6 వారాల పూర్తి జీతంతో కూడిన సెలవులు ఉంటాయి.
"""

# 2. చంకింగ్ ఫంక్షన్ (ఓవర్‌ల్యాప్‌తో)
def split_document(text: str, chunk_size: int = 250, overlap: int = 50) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        chunk = text[start:start + chunk_size].strip()
        if len(chunk) > 20:
            chunks.append(chunk)
        start += (chunk_size - overlap)
    return chunks

chunks = split_document(COMPANY_POLICY_DOC)
print(f"డాక్యుమెంట్ నుండి {len(chunks)} చంకులు తయారు చేయబడ్డాయి.")

# 3. ChromaDB లో స్టోర్ చేయడం
chroma_client = chromadb.Client()
policy_collection = chroma_client.create_collection("techin_handbook")

policy_collection.add(
    documents=chunks,
    metadatas=[{"source": "Employee_Handbook_2026.pdf", "chunk_id": f"chunk_{i}"} for i in range(len(chunks))],
    ids=[f"id_{i}" for i in range(len(chunks))]
)

# 4. RAG క్వెరీ పైప్‌లైన్
def query_rag_pipeline(user_query: str):
    # సంబంధిత 2 చంకులను వెక్టర్ డేటాబేస్ నుండి తేవడం
    results = policy_collection.query(query_texts=[user_query], n_results=2)
    retrieved_texts = results["documents"][0]
    
    context_block = "\n---\n".join(retrieved_texts)
    
    prompt = f"""
    కేవలం కింద ఇచ్చిన సమాచారం ఆధారంగా మాత్రమే ప్రశ్నకు సమాధానం ఇవ్వు.
    సమాచారం లేకపోతే: "ఈ సమాచారం హ్యాండ్‌బుక్‌లో లేదు" అని చెప్పు.

    <context>
    {context_block}
    </context>

    ప్రశ్న: {user_query}
    """
    
    # 5. జెమిని మోడల్ ద్వారా గ్రౌండెడ్ సమాధానం
    gemini_client = genai.Client()
    response = gemini_client.models.generate_content(
        model="gemini-1.5-flash",
        contents=prompt,
        config=types.GenerateContentConfig(temperature=0.0)
    )

    print("\n" + "="*55)
    print(f"యూజర్ ప్రశ్న : {user_query}")
    print(f"డేటాబేస్ నుండి వచ్చిన సమాచారం:\n{context_block}")
    print("\nAI నిజాయితీతో కూడిన సమాధానం:")
    print(response.text.strip())
```

## 7. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: RAG పైప్‌లైన్లలో చంక్ ఓవర్‌ల్యాప్ (Chunk Overlap) ఎందుకు అవసరం?**
   - **సమాధానం:** చంకింగ్ చేసేటప్పుడు ఒక వాక్యం లేదా అర్థవంతమైన ఆలోచన మధ్యలోనే తెగిపోకుండా కాపాడటానికి చంక్ ఓవర్‌ల్యాప్ అవసరం. ఒక చంక్ చివర ఉన్న కొంత సమాచారాన్ని తర్వాతి చంక్ ప్రారంభంలో మళ్లీ పునరావృతం చేయడం వల్ల, రెండు పక్కపక్క చంకులలోనూ సందర్భం (Context) చెడిపోకుండా ఉంటుంది.
2. **ప్రశ్న: LLM లలో అబద్ధాలు చెప్పే (Hallucination) సమస్యను RAG ఎలా అరికడుతుంది?**
   - **సమాధానం:** బేస్ మోడల్స్ గతంలో నేర్చుకున్న విషయాలను సరిగ్గా గుర్తుతెచ్చుకోలేక అబద్ధాలు చెబుతాయి. RAG ఏం చేస్తుందంటే, ప్రశ్న రాగానే బయటి నమ్మకమైన డేటాబేస్ నుండి అసలైన డాక్యుమెంట్ పేరాగ్రాఫ్‌లను వెతికి తీసుకొచ్చి మోడల్‌కి ఇస్తుంది. మరియు సిస్టమ్ ప్రాంప్ట్ ద్వారా "కేవలం ఈ ఆధారాలు చూసి మాత్రమే మాట్లాడు" అని కట్టడి చేయడం వల్ల మోడల్ సొంతంగా అబద్ధాలు చెప్పలేదు.
3. **ప్రశ్న: డెన్స్ రిట్రీవల్ (Dense) మరియు స్పార్స్ రిట్రీవల్ (Sparse) మధ్య తేడా ఏమిటి?**
   - **సమాధానం:** **డెన్స్ రిట్రీవల్** న్యూరల్ ఎంబెడ్డింగ్స్ ద్వారా భావం (Meaning) ఆధారంగా వెతుకుతుంది (ఉదాహరణకి "కారు" అంటే "వాహనం" అని గుర్తిస్తుంది). **స్పార్స్ రిట్రీవల్** (ఉదా: BM25) కచ్చితమైన అక్షరాలు, పదాల ఫ్రీక్వెన్సీ ఆధారంగా వెతుకుతుంది (ఉదాహరణకి "పార్ట్ నంబర్ #AB-9021" లాంటి ఖచ్చితమైన ఐడీల కోసం). ఆధునిక RAG లో ఈ రెండింటినీ కలిపి **హైబ్రిడ్ సెర్చ్** ఉపయోగిస్తారు.
