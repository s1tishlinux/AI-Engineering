## 1. మనుషుల భావాలను SQL ఎందుకు అర్థం చేసుకోలేదు? (The "Why")

ఒక ఉద్యోగి కంపెనీ HR డేటాబేస్‌లో ఇలా వెతికారని అనుకుందాం:
> *"నా పెళ్లి కోసం సెలవులు ఎలా దరఖాస్తు చేసుకోవాలి?"*

- సాధారణ SQL లో `SELECT * FROM policies WHERE text LIKE '%పెళ్లి%'` అని కొడితే **0 ఫలితాలు వస్తాయి!** ఎందుకంటే HR పుస్తకంలో దాన్ని *"వివాహ సంబంధిత ప్రత్యేక సెలవు నిబంధన"* అని రాసి ఉంటుంది.
- SQL కేవలం అక్షరాలు మ్యాచ్ అయ్యాయో లేదో మాత్రమే చూస్తుంది తప్ప, **భావాన్ని (Meaning) అర్థం చేసుకోలేదు**.

**ఎంబెడ్డింగ్స్ ఈ సమస్యను ఎలా పరిష్కరిస్తాయి?**
- కంప్యూటర్ ఆ వాక్యంలోని భావాన్ని ఒక వెక్టర్ స్పేస్‌లో నంబర్లుగా (GPS కోఆర్డినేట్స్ లాగా) మారుస్తుంది.
- *"పెళ్లి"* అనే మాటకు మరియు *"వివాహం"* అనే మాటకు వెక్టర్ స్పేస్‌లో పక్కపక్కనే స్థానం లభిస్తుంది!

## 2. వెక్టర్ పోలికల కొలమానాలు (Similarity Metrics)

```
         వెక్టర్ A                     వెక్టర్ A
           ▲                            ▲
           │ \ θ (కోణం - Angle)         │
           │  \                         │  దూరం (L2 Distance)
           │   \                        │ ◄──────────► వెక్టర్ B
           └────► వెక్టర్ B              └────────────────────►
        Cosine Similarity                   Euclidean (L2)
```

| కొలమానం | ఫార్ములా | ఏం కొలుస్తుంది? | ఎప్పుడు వాడాలి? |
| :--- | :--- | :--- | :--- |
| **Cosine Similarity** | $\frac{A \cdot B}{\|A\| \|B\|}$ | రెండు వెక్టర్ల మధ్య ఉండే **కోణం (Angle)**. పరిధి: $[-1, 1]$. | **టెక్స్ట్ మరియు NLP కోసం ఇదే నెంబర్ 1 ఎంపిక!** |
| **Dot Product** | $A \cdot B = \sum A_i B_i$ | కోణం మరియు పొడవు రెండూ. | నార్మలైజ్ చేసిన వెక్టర్లకు అత్యంత వేగంగా లెక్కించడానికి |
| **Euclidean Distance ($L2$)** | $\sqrt{\sum (A_i - B_i)^2}$ | రెండు బిందువుల మధ్య నేరుగా ఉండే దూరం. | K-Means క్లస్టరింగ్, జియో లొకేషన్లలో |

## 3. వెక్టర్ డేటాబేస్: ChromaDB తో ప్రాక్టికల్ కోడ్

ప్రపంచవ్యాప్తంగా డెవలపర్లు RAG ప్రాజెక్టుల కోసం అత్యధికంగా వాడే వెక్టర్ డేటాబేస్ **ChromaDB**.

### స్టెప్ 1: ChromaDB ఇన్‌స్టాల్ చేయడం
```bash
pip install chromadb
```

### స్టెప్ 2: డాక్యుమెంట్లను ఎంబెడ్ చేసి వెతకడం
```python
import chromadb

# 1. క్లయింట్ ప్రారంభం
client = chromadb.Client()

# 2. కలెక్షన్ క్రియేట్ చేయడం (SQL లో Table లాంటిది)
# ChromaDB ఆటోమేటిక్‌గా అన్ని వాక్యాలను ఎంబెడ్డింగ్స్‌గా మారుస్తుంది!
collection = client.create_collection(name="company_hr_policies")

# 3. డాక్యుమెంట్లు, మెటాడేటా మరియు ID లను జతచేయడం
documents = [
    "ఉద్యోగులకు సంవత్సరానికి 20 రోజుల పెయిడ్ యాన్యువల్ సెలవులు ఉంటాయి.",
    "IT విభాగం సీనియర్ ఇంజనీర్లకు 32GB RAM గల మ్యాక్‌బుక్ ప్రో ల్యాప్‌టాప్‌లను అందిస్తుంది.",
    "వివాహం చేసుకున్నప్పుడు 5 రోజుల పాటు ప్రత్యేక వివాహ సెలవులు మంజూరు చేయబడతాయి.",
    "కంపెనీ హెల్త్ ఇన్సూరెన్స్ ప్రతి కుటుంబ సభ్యుడికి ₹5,00,000 వరకు వర్తిస్తుంది."
]

metadatas = [
    {"category": "leave", "dept": "HR"},
    {"category": "hardware", "dept": "IT"},
    {"category": "leave", "dept": "HR"},
    {"category": "benefits", "dept": "HR"}
]

ids = ["doc_01", "doc_02", "doc_03", "doc_04"]

collection.add(documents=documents, metadatas=metadatas, ids=ids)
print(f"✅ ChromaDB లోకి {collection.count()} డాక్యుమెంట్లు చేర్చబడ్డాయి.\n")

# 4. సెమాంటిక్ సెర్చ్: కచ్చితమైన కీవర్డ్స్ లేకుండా భావం ఆధారంగా వెతకడం!
query = "నాకు వచ్చే నెల పెళ్లి ఉంది, నేను అదనపు సెలవులు తీసుకోవచ్చా?"
results = collection.query(
    query_texts=[query],
    n_results=1,
    where={"category": "leave"}  # కేవలం లీవ్ కేటగిరీలోనే వెతకమని మెటాడేటా ఫిల్టర్!
)

print(f"యూజర్ అడిగిన ప్రశ్న: '{query}'\n")
print("వెక్టర్ డేటాబేస్ కనుగొన్న సరైన సమాధానం:")
print("👉", results["documents"][0][0])
print(f"(దూరం స్కోర్: {results['distances'][0][0]:.4f})")
```

## 4. మెటా వారి FAISS (కోట్లాది వెక్టర్లలో మెరుపు వేగంతో సెర్చ్)

మీ వద్ద **1 కోటి డాక్యుమెంట్లు** ఉన్నప్పుడు సాధారణ పైథాన్ లూప్స్ పనిచేయవు. Facebook AI వారు కనిపెట్టిన **FAISS** C++ వేగంతో క్షణంలో సమీప వెక్టర్లను పట్టుకుంటుంది.

```python
import numpy as np
import faiss

# 4-డైమెన్షన్ల వెక్టర్లు (ఉదాహరణ కోసం)
dimension = 4
num_vectors = 1000

# 1,000 డాక్యుమెంట్ వెక్టర్లను తయారు చేశాం
np.random.seed(42)
document_vectors = np.random.random((num_vectors, dimension)).astype("float32")

# 1. FAISS ఇండెక్స్ నిర్మించడం
index = faiss.IndexFlatL2(dimension)
index.add(document_vectors)
print(f"FAISS ఇండెక్స్‌లో మొత్తం {index.ntotal} వెక్టర్లు సిద్ధంగా ఉన్నాయి.")

# 2. కొత్త క్వెరీ వెక్టర్‌తో వెతకడం
query_vector = np.random.random((1, dimension)).astype("float32")
top_k = 3
distances, indices = index.search(query_vector, top_k)

print("\nఅత్యంత దగ్గరగా ఉన్న టాప్ 3 డాక్యుమెంట్ల ఇండెక్స్‌లు:", indices[0])
print("వాటి మధ్య ఉన్న దూరం:", distances[0])
```

## 5. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **రెండు వేర్వేరు ఎంబెడ్డింగ్ మోడల్స్ కలపడం:**
   - ⚠️ **అత్యంత ఘోరమైన తప్పు:** డాక్యుమెంట్లను OpenAI ఎంబెడ్డింగ్ మోడల్‌తో సేవ్ చేసి, ప్రశ్నను Google Gemini ఎంబెడ్డింగ్ మోడల్‌తో వెతకడానికి ప్రయత్నించడం! రెండు మోడల్స్ కొలతలు పూర్తిగా వేర్వేరు. డాక్యుమెంట్లకీ మరియు ప్రశ్నలకీ **ఒకే ఒక్క మోడల్** వాడాలి!
2. **మెటాడేటా ఫిల్టరింగ్ వాడకపోవడం:**
   - మొత్తం కంపెనీ ఫైల్స్‌లో ఫిల్టర్ లేకుండా వెతికితే, ఫైనాన్స్ ప్రశ్నకి సంబంధం లేని ఇంజనీరింగ్ డాక్యుమెంట్లు వచ్చే ప్రమాదం ఉంది.
3. **దూరం (Distance) మరియు పోలిక (Similarity) ల తేడా మర్చిపోవడం:**
   - Cosine **Similarity** లో 1.0 అంటే పూర్తి పోలిక. Cosine **Distance** లో 0.0 అంటే పూర్తి పోలిక (దూరం సున్నా అంటే రెండూ ఒకే చోట ఉన్నాయి).

## 6. ప్రాక్టీస్ ల్యాబ్ (Daily Hands-On Lab)

### 🧪 టాస్క్: కస్టమర్ కేర్ FAQ మ్యాచ్ ఇంజిన్
**సన్నివేశం:** కస్టమర్ తన సమస్యను సాధారణ మాటల్లో చెబుతాడు (*"నా అకౌంట్ నుండి ఒకే ఆర్డర్‌కి రెండుసార్లు డబ్బులు కట్ అయ్యాయి"*). ChromaDB లోని FAQ లను పోల్చి, సరైన సమాధానం ఇవ్వండి. ఒకవేళ ఏ FAQ మ్యాచ్ కాకపోతే మనుషులకు కనెక్ట్ చేసేలా రూల్ రాయండి.

```python
# =========================================================
# Day 26 Lab: సెమాంటిక్ FAQ మ్యాచర్ (ChromaDB)
# =========================================================
import chromadb

client = chromadb.Client()
faq_collection = client.create_collection(
    name="ecommerce_faqs",
    metadata={"hnsw:space": "cosine"}
)

# కంపెనీ FAQ రికార్డులు
faq_entries = [
    {"id": "faq_01", "q": "పాడైపోయిన వస్తువుకు రీఫండ్ ఎలా పొందాలి?", "ans": "ఆర్డర్స్ పేజీకి వెళ్లి రిటర్న్ ఐటమ్ క్లిక్ చేసి 48 గంటల్లో ఫోటోలు అప్‌లోడ్ చేయండి."},
    {"id": "faq_02", "q": "ఒకే ఆర్డర్‌కి రెండుసార్లు డబ్బులు ఎందుకు కట్ అయ్యాయి?", "ans": "డూప్లికేట్ ఛార్జీలు తాత్కాలిక హోల్డ్ మాత్రమే; 3-5 రోజుల్లో మీ బ్యాంక్ ఖాతాలోకి వాపస్ వస్తాయి."},
    {"id": "faq_03", "q": "డెలివరీ అడ్రస్ ఎలా మార్చుకోవాలి?", "ans": "వస్తువు డిస్పాచ్ కాకముందు మాత్రమే ఆర్డర్స్ ట్యాబ్‌లో అడ్రస్ మార్చవచ్చు."},
]

faq_collection.add(
    documents=[entry["q"] for entry in faq_entries],
    metadatas=[{"answer": entry["ans"]} for entry in faq_entries],
    ids=[entry["id"] for entry in faq_entries]
)

def resolve_customer_query(customer_question: str, max_distance_threshold: float = 0.5):
    results = faq_collection.query(
        query_texts=[customer_question],
        n_results=1
    )
    
    distance = results["distances"][0][0]
    matched_q = results["documents"][0][0]
    answer = results["metadatas"][0][0]["answer"]

    print("="*55)
    print(f"కస్టమర్ అడిగిన ప్రశ్న : '{customer_question}'")
    print(f"సరిపోలిన FAQ ప్రశ్న    : '{matched_q}'")
    print(f"దూరం స్కోర్ (Distance) : {distance:.4f}")

    if distance > max_distance_threshold:
        print("⚠️ కస్టమర్ కేర్ ఎగ్జిక్యూటివ్‌కి బదిలీ చేస్తున్నాం: సమాధానం దొరకలేదు.")
    else:
        print(f"✅ ఆటోమేటిక్ సమాధానం : {answer}")
    print("="*55)

# టెస్ట్ 1: డబుల్ పేమెంట్ సమస్య
resolve_customer_query("నేను ఒక్కసారే కొన్నాను కానీ బ్యాంక్ స్టేట్‌మెంట్‌లో రెండుసార్లు డబ్బులు పోయాయి.")

# టెస్ట్ 2: సంబంధం లేని ప్రశ్న (తిరస్కరించాలి)
resolve_customer_query("చికెన్ బిర్యానీ ఎలా తయారు చేయాలి?")
```

## 7. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: Curse of Dimensionality అంటే ఏమిటి? అది వెక్టర్ ఎంబెడ్డింగ్స్‌ను ఎలా ప్రభావితం చేస్తుంది?**
   - **సమాధానం:** వెక్టర్ కొలతలు (Dimensions) విపరీతంగా పెరిగేకొద్దీ (ఉదాహరణకు 1536 డైమెన్షన్లు), ఆ స్పేస్ యొక్క వైశాల్యం పెరిగిపోయి డేటా పాయింట్లు చాలా దూరంగా చెల్లాచెదురైపోతాయి. దీనివల్ల యూక్లిడియన్ దూరం ($L2$) తన ప్రాముఖ్యతను కోల్పోతుంది (అన్ని పాయింట్ల మధ్య దూరం సమానంగా కనిపిస్తుంది). అందుకే ఎక్కువ డైమెన్షన్లు ఉన్నప్పుడు దూరం బదులు కోణాన్ని (Angle) కొలిచే **Cosine Similarity** ని ఉపయోగిస్తాం.
2. **ప్రశ్న: వెక్టర్ డేటాబేస్‌లలో HNSW (Hierarchical Navigable Small World) ఇండెక్స్ ఎలా పనిచేస్తుంది?**
   - **సమాధానం:** HNSW అనేది గ్రాఫ్-బేస్డ్ అల్గారిథమ్. ఇది వెక్టర్లను వేర్వేరు లేయర్లతో కూడిన ఒక నెట్‌వర్క్ గ్రాఫ్‌గా అమరుస్తుంది (మల్టీ-లేయర్ స్కిప్ లిస్ట్ లాగా). దీనివల్ల కోట్లాది వెక్టర్లలో వెతికేటప్పుడు ప్రతి వెక్టర్‌నూ బ్రూట్-ఫోర్స్ ($O(N)$) గా తనిఖీ చేయకుండా, లాగరిథమిక్ టైమ్ ($O(\log N)$) లో క్షణంలో అత్యంత సమీప పొరుగు వెక్టర్లను (Approximate Nearest Neighbors) గుర్తిస్తుంది.
3. **ప్రశ్న: రెండు వేర్వేరు ఎంబెడ్డింగ్ మోడల్స్ నుండి వచ్చిన వెక్టర్లను నేరుగా పోల్చవచ్చా?**
   - **సమాధానం:** అస్సలు పోల్చలేము! ఎందుకంటే ప్రతి ఎంబెడ్డింగ్ మోడల్ తన సొంత పదజాలం మరియు న్యూరల్ నెట్‌వర్క్ వెయిట్స్‌తో భావాలను ఒక ప్రత్యేకమైన కోఆర్డినేట్ స్పేస్‌లోకి మ్యాప్ చేస్తుంది. ఒక మోడల్ వెక్టర్‌ను ఇంకో మోడల్ వెక్టర్‌తో పోల్చడం అంటే భూమిపై ఉన్న GPS అక్షాంశాలను టీవీ స్క్రీన్ పిక్సెల్ నంబర్లతో పోల్చడం లాంటిది (వాటికి ఎలాంటి పోలికా ఉండదు).
