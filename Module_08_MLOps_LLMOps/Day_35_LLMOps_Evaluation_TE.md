## 1. ఈ రోజు మన గోల్స్ (Day 35 Learning Objectives)
- జనరేటివ్ AI మరియు LLM ల విషయంలో సాధారణ Accuracy, F1-Score లాంటి సాంప్రదాయ మెట్రిక్స్ ఎందుకు పనిచేయవు?
- **RAG Triad** లోని 3 కీలక సూత్రాలు: **Faithfulness (విశ్వసనీయత/గ్రాండెడ్‌నెస్)**, **Answer Relevance (సమాధాన ఔచిత్యం)**, మరియు **Context Precision/Recall**.
- ప్రొడక్షన్ లో LLM రెస్పాన్స్ లను నిరంతరం గమనించడానికి **LLM Tracing & Observability** (టోకెన్ ఖర్చులు, లేటెన్సీ, స్పేన్ లాగ్స్) అమలు చేయడం.
- పైథాన్ కోడ్ లో ప్రాంప్ట్‌లను హార్డ్‌కోడ్ చేయకుండా **Prompt Versioning** నిర్వహించడం.
- యూజర్లు ఫిర్యాదు చేయకముందే తప్పుడు సమాచారాన్ని (Hallucinations) పసిగట్టే **LLM-as-a-Judge** ఆటోమేటెడ్ ఎవాల్యుయేషన్ ఇంజిన్ ని రూపొందించడం.

## 2. రియల్ వరల్డ్ అనలాజీ (Real-World Analogy)

> 💡 **అనలాజీ: ఆబ్జెక్టివ్ ఎగ్జామ్ పేపర్ దిద్దడం vs సివిల్స్ వ్యాసం (Essay) దిద్దడం**
>
> - **సాధారణ MLOps (మల్టిపుల్ ఛాయిస్ పరీక్ష):**
>   ఒక బ్యాంక్ లోన్ అప్రూవల్ మోడల్ లేదా స్పామ్ డిటెక్టర్ ని ఎవాల్యుయేట్ చేయడం OMR షీట్ దిద్దినట్లు ఉంటుంది. ప్రశ్న 1: జవాబు B నా కాదా? అవును అంటే 1 మార్కు, కాకపోతే 0 మార్కులు. ఇది ఖచ్చితమైన గణిత సూత్రం.
> - **LLMOps (సివిల్స్ వ్యాసం లేదా డాక్టర్ ప్రిస్క్రిప్షన్ దిద్దడం):**
>   ఒక LLM ఒక రోగి వ్యాధి లక్షణాలపై 300 పదాల పేరా రాసింది. ఇందులో 14వ పదం పలానా నిఘంటువుతో మ్యాచ్ అయిందా అని OMR లా చెక్ చేయలేము.
>   దీనికోసం ఒక సీనియర్ ప్రొఫెసర్ (లేదా ఆటోమేటెడ్ **LLM-as-a-Judge**) వచ్చి కింది 3 ప్రశ్నలు అడగాలి:
>   1. **Faithfulness:** మెడికల్ బుక్ లో లేని అబద్ధాలను తనంతట తాను కల్పించి రాసిందా? (Hallucination చెక్)
>   2. **Answer Relevance:** పేషెంట్ అడిగిన అసలు ప్రశ్నకు సూటిగా సమాధానం ఇచ్చిందా?
>   3. **Context Recall:** మెడికల్ రికార్డుల్లో ఉన్న ముఖ్యమైన ఎలర్జీ విషయాలను మర్చిపోయిందా?

## 4. RAG Triad లోని 3 ప్రధాన మెట్రిక్స్

1. **Faithfulness (గ్రాండెడ్‌నెస్ / వాస్తవికత):**
   - *ప్రశ్న:* సమాధానంలో రాసిన ప్రతి వాక్యం వెక్టర్ డేటాబేస్ నుండి తెచ్చిన సమాచారంలో ఉందా?
   - *ఉద్దేశం:* AI తనంతట తాను సొంతంగా కల్పించే అబద్ధాలను (Hallucinations) పట్టుకుంటుంది.
2. **Answer Relevance (సమాధాన ఔచిత్యం):**
   - *ప్రశ్న:* యూజర్ అడిగిన ప్రశ్నకు ఇది సూటిగా సమాధానం ఇస్తుందా, లేక సంబంధం లేని విషయాలు చెప్తోందా?
   - *ఉద్దేశం:* ప్రశ్నను దాటవేయకుండా సరైన జవాబు వస్తుందో లేదో చూస్తుంది.
3. **Context Precision & Recall:**
   - *ప్రశ్న:* సమాధానం ఇవ్వడానికి అవసరమైన అసలైన సమాచార చంక్స్ ని వెక్టర్ సెర్చ్ సరిగ్గా తీసుకువచ్చిందా?
   - *ఉద్దేశం:* చెత్త చంక్స్ ని ఫిల్టర్ చేసి, సరైన కాంటెక్స్ట్ ని అందిస్తుంది.

## 5. కోడింగ్ వాక్‌త్రూ: స్వచ్ఛమైన Python లో Faithfulness Evaluator

కింది కోడ్ ఒక LLM రెస్పాన్స్ లోని వాక్యాలను విడదీసి, అవి వెక్టర్ డాక్యుమెంట్ లో ఉన్నాయో లేదో పరిశీలించి గణిత శాస్త్ర ప్రకారమైన **Faithfulness Score** ను ఎలా గణిస్తుందో వివరిస్తుంది:

```python
# evaluate_faithfulness.py
import json

# మాక్ LLM-as-a-Judge API
def mock_judge_llm(prompt: str) -> str:
    if "క్లెయిమ్స్ వెలికితీయి" in prompt:
        return json.dumps({
            "claims": [
                "పైథాన్ ను గైడో వాన్ రోసమ్ కనుగొన్నారు.",
                "పైథాన్ 1991 లో విడుదలయింది.",
                "పైథాన్ ప్రాథమికంగా కేవలం C కంపైలర్ కోసం మాత్రమే డిజైన్ చేయబడింది."  # తప్పుడు సమాచారం (Hallucination)
            ]
        })
    elif "డాక్యుమెంట్ లో ఉందో లేదో వెరిఫై చేయి" in prompt:
        return json.dumps({
            "results": [
                {"claim": "పైథాన్ ను గైడో వాన్ రోసమ్ కనుగొన్నారు.", "supported": True, "reason": "డాక్యుమెంట్ లో స్పష్టంగా ఉంది."},
                {"claim": "పైథాన్ 1991 లో విడుదలయింది.", "supported": True, "reason": "డాక్యుమెంట్ లో స్పష్టంగా ఉంది."},
                {"claim": "పైథాన్ ప్రాథమికంగా కేవలం C కంపైలర్ కోసం మాత్రమే డిజైన్ చేయబడింది.", "supported": False, "reason": "ఇది అబద్ధం, డాక్యుమెంట్ లో పైథాన్ ఇంటర్‌ప్రీటెడ్ అని ఉంది."}
            ]
        })
    return "{}"

class LocalFaithfulnessEvaluator:
    def evaluate(self, answer: str, context: str) -> dict:
        # 1. రెస్పాన్స్ నుండి ప్రతి వాస్తవ వాక్యాన్ని (Claim) వేరు చేయడం
        prompt_1 = f"ఈ సమాధానం నుండి ప్రతి క్లెయిమ్స్ వెలికితీయి: {answer}"
        claims_data = json.loads(mock_judge_llm(prompt_1)).get("claims", [])

        # 2. ఆ క్లెయిమ్ కాంటెక్స్ట్ లో ఉందో లేదో చెక్ చేయడం
        prompt_2 = f"ఈ కాంటెక్స్ట్ ఆధారంగా: {context}\nక్లెయిమ్స్ డాక్యుమెంట్ లో ఉందో లేదో వెరిఫై చేయి: {claims_data}"
        verification = json.loads(mock_judge_llm(prompt_2)).get("results", [])

        # 3. స్కోరు గణన: (నిజమైన క్లెయిమ్స్ సంఖ్య / మొత్తం క్లెయిమ్స్ సంఖ్య)
        total_claims = len(verification)
        supported_claims = sum(1 for v in verification if v["supported"] is True)
        
        score = supported_claims / total_claims if total_claims > 0 else 0.0

        return {
            "faithfulness_score": round(score, 2),
            "total_claims": total_claims,
            "supported_claims": supported_claims,
            "has_hallucination": score < 1.0,
            "details": verification
        }

if __name__ == "__main__":
    context = "పైథాన్ ఒక ఇంటర్‌ప్రీటెడ్ ప్రోగ్రామింగ్ భాష. దీనిని గైడో వాన్ రోసమ్ అభివృద్ధి చేసి 1991 లో విడుదల చేశారు."
    generated_answer = "పైథాన్ ను గైడో వాన్ రోసమ్ 1991 లో కనుగొన్నారు. ఇది ప్రాథమికంగా కేవలం C కంపైలర్ కోసం డిజైన్ చేయబడింది."

    evaluator = LocalFaithfulnessEvaluator()
    report = evaluator.evaluate(answer=generated_answer, context=context)

    print("\n--- 📊 LLMOps ఎవాల్యుయేషన్ రిపోర్ట్ ---")
    print(f"విశ్వసనీయత స్కోరు (Faithfulness) : {report['faithfulness_score'] * 100}%")
    print(f"మొత్తం క్లెయిమ్స్                  : {report['total_claims']}")
    print(f"సత్యమైన క్లెయిమ్స్                : {report['supported_claims']}")
    print(f"హాలూసినేషన్ (అబద్ధం) ఉందా?       : {'🚨 అవును, ఉంది!' if report['has_hallucination'] else '✅ లేదు'}")
    
    print("\nవివరణాత్మక పరిశీలన:")
    for d in report["details"]:
        status = "✅ నిజం" if d["supported"] else "❌ హాలూసినేషన్"
        print(f"[{status}]: {d['claim']}")
        print(f"   కారణం: {d['reason']}")
```

## 6. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు

| తప్పు | ఎందుకు సమస్య వస్తుంది? | సరైన పద్ధతి |
| :--- | :--- | :--- |
| **LLM సమాధానాలను BLEU / ROUGE స్కోర్లతో కొలవడం** | ఇంగ్లీష్ లో ఒకే విషయాన్ని పది రకాలుగా చెప్పవచ్చు. పదం టు పదం సరిపోలకపోయినా సమాధానం కరెక్ట్ కావచ్చు. | ఎంబెడ్డింగ్స్ ఆధారిత సెమాంటిక్ సిమిలారిటీ లేదా LLM-as-a-Judge పద్ధతులను వాడాలి. |
| **ప్రొడక్షన్ లో ట్రేసింగ్ (Tracing) లేకపోవడం** | కస్టమర్ తప్పుడు సమాధానం వచ్చిందని కంప్లైంట్ ఇచ్చినప్పుడు, వెక్టర్ డేటాబేస్ నుండి ఏ చంక్ వచ్చింది, ప్రాంప్ట్ లో ఏముందో తెలియక డీబగ్ చేయడం అసాధ్యమవుతుంది. | ప్రతి రిక్వెస్ట్ కి Langfuse లేదా OpenTelemetry ట్రేసింగ్ ఐడీ జనరేట్ చేసి లాగ్ చేయాలి. |
| **కోడ్ లోపలే ప్రాంప్ట్ టెక్స్ట్‌ను రాయడం** | ప్రాంప్ట్ లో ఒక్క పదం మార్చాలన్నా మళ్ళీ కోడ్ మొత్తాన్ని డిప్లాయ్ చేయాల్సి వస్తుంది. | ప్రాంప్ట్‌లను ప్రత్యేకమైన YAML లేదా ప్రాంప్ట్ రిజిస్ట్రీలలో వర్షన్ నంబర్లతో (`v1.0`, `v2.0`) నిర్వహించాలి. |

## 7. ప్రాక్టికల్ ల్యాబ్ (Hands-on Lab)

### లక్ష్యం:
ఒక పైథాన్ డెకరేటర్ లేదా ఫంక్షన్ రాసి, ప్రతి LLM కాల్ కి ఎంత సమయం (Milliseconds) పట్టింది, ఎన్ని టోకెన్లు ఖర్చయ్యాయి, మరియు ఎంత ఖర్చు (Cost in USD) అయిందో ప్రింట్ చేసే చిన్న అబ్జర్వబిలిటీ టూల్ తయారుచేయండి.

```python
# lab_day35_telemetry.py
import time

def log_llm_telemetry(prompt: str, response: str):
    start = time.perf_counter()
    time.sleep(0.1)  # సిమ్యులేటెడ్ నెట్‌వర్క్ సమయం
    latency_ms = (time.perf_counter() - start) * 1000
    
    tokens_in = len(prompt.split()) * 2
    tokens_out = len(response.split()) * 2
    
    cost_usd = ((tokens_in * 0.0015) + (tokens_out * 0.002)) / 1000
    
    print(f"⏱️ సమయం: {latency_ms:.2f} ms | 🔢 టోకెన్లు: {tokens_in + tokens_out} | 💰 ఖర్చు: ${cost_usd:.6f}")

log_llm_telemetry("హైదరాబాద్ రాజధాని ఏది?", "తెలంగాణ రాజధాని హైదరాబాద్.")
```

## 8. టాప్ 3 ఇంటర్వ్యూ ప్రశ్నలు & సమాధానాలు

### Q1: RAG Triad అంటే ఏమిటి?
**సమాధానం:**
RAG అప్లికేషన్ల నాణ్యతను కొలవడానికి రూపొందించబడిన 3 ముఖ్యమైన మెట్రిక్స్:
1. **Faithfulness:** ఇచ్చిన డాక్యుమెంట్స్ ఆధారంగానే సమాధానం ఉందా లేదా (హాలూసినేషన్ చెక్).
2. **Answer Relevance:** యూజర్ అడిగిన ప్రశ్నకు తగిన సమాధానమేనా కాదా.
3. **Context Relevance / Precision:** వెక్టర్ డేటాబేస్ నుండి తీసుకువచ్చిన డాక్యుమెంట్లలో అనవసరమైన చెత్త లేకుండా సరైన సమాచారం మాత్రమే ఉందా లేదా.

### Q2: LLM-as-a-Judge విధానంలో ఉండే ప్రధాన పరిమితులు ఏమిటి?
**సమాధానం:**
1. **ఖర్చు & సమయం:** ప్రతి సమాధానాన్ని వేరొక పెద్ద మోడల్ (GPT-4) తో ఎవాల్యుయేట్ చేయించడం వల్ల ఖర్చు మరియు లేటెన్సీ పెరుగుతాయి.
2. **Verbosity Bias:** ఎక్కువ పేరాలు రాసిన సమాధానాలను జడ్జి మోడల్స్ సహజంగా మంచి సమాధానాలుగా భావించే అవకాశం ఉంది.
3. **Self-Enhancement Bias:** కొన్ని మోడల్స్ తమ కంపెనీ మోడల్స్ రూపొందించిన సమాధానాలకే ఎక్కువ మార్కులు ఇచ్చే పక్షపాతం చూపిస్తాయి.

### Q3: LLMOps లో ట్రేసింగ్ (Tracing) ఎందుకు అవసరం?
**సమాధానం:**
ఒక ఏజెంట్ లేదా RAG సిస్టమ్ లో యూజర్ ప్రాంప్ట్ రాగానే ఎంబెడ్డింగ్ సెర్చ్, క్వెరీ రీరైటింగ్, టూల్ ఎగ్జిక్యూషన్ మరియు ఫైనల్ ఆన్సర్ వంటి అనేక స్టెప్స్ ఉంటాయి. ఎక్కడ లోపం జరిగిందో, ఏ స్టెప్ కి ఎక్కువ సమయం పట్టిందో, ఎన్ని టోకెన్లు ఖర్చయ్యాయో ఒకే స్పేన్ వ్యూ లో డీబగ్ చేయడానికి Tracing అత్యంత ఆవశ్యకం.
