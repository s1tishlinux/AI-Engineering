## 1. ఈ రోజు మన గోల్స్ (Day 36 Learning Objectives)
- ప్రొడక్షన్ లో మెషిన్ లెర్నింగ్ మోడల్స్ ఎందుకు ఫెయిల్ అవుతాయి? **Data Drift (Covariate Shift)** vs. **Concept Drift** ల మధ్య తేడా తెలుసుకోవడం.
- గణాంక శాస్త్ర ఆధారిత డ్రిఫ్ట్ డిటెక్షన్ సూత్రాలు: **KS-Test (Kolmogorov-Smirnov)** మరియు **PSI (Population Stability Index)** లను పైథాన్ లో లెక్కించడం.
- ప్రొడక్షన్ లో వచ్చే లక్షలాది లైవ్ రిక్వెస్ట్‌లను డేటా లేక్ (S3/Parquet) లో స్టోర్ చేసి రోజూ రాత్రి డ్రిఫ్ట్ అనాలిసిస్ రన్ చేసే ఆర్కిటెక్చర్.
- అలర్ట్ మెకానిజమ్: డేటా తీవ్రంగా మారినప్పుడు ఆటోమేటిక్ గా కొత్త డేటాతో మోడల్ ని తిరిగి ట్రైన్ చేసేలా **Retraining Triggers** సెటప్ చేయడం.
- **Silent Failures (సైలెంట్ ఫెయిల్యూర్స్):** సర్వర్ లో ఎలాంటి ఎర్రర్ రాకుండా (HTTP 200 OK ఇస్తూనే) తప్పుడు ప్రిడిక్షన్స్ ఇవ్వడం అంటే ఏమిటి? దాన్ని ఎలా పసిగట్టాలి?

## 2. రియల్ వరల్డ్ అనలాజీ (Real-World Analogy)

> 💡 **అనలాజీ: ఎడారి వాతావరణం కోసం తయారైన రాడార్ vs శీతాకాల మార్పు**
>
> - **డేటా డ్రిఫ్ట్ (Data Drift - Covariate Shift):**
>   దుబాయ్ ఎడారిలో ఉష్ణోగ్రత 35°C నుండి 48°C వరకు ఉంటుంది. అక్కడ ఒక AI మోడల్ ని తయారుచేసి, ప్రజలు ఎప్పుడు కోట్లు వేసుకుంటారో అంచనా వేశారు. ఆ తర్వాత అదే మోడల్ ని హిమాలయాల్లో (-10°C ఉండే చోట) పెట్టారు.
>   ఇక్కడ మనుషులు చలికి కోట్ వేసుకుంటారు అనే లాజిక్ మారలేదు, కానీ AI మోడల్ కి ఇన్పుట్ గా వచ్చే **ఉష్ణోగ్రత డేటా పంపిణీ ($P(X)$)** పూర్తిగా మారిపోయింది! మోడల్ ఎప్పుడూ అంత మైనస్ డిగ్రీలను చూడలేదు.
> - **కాన్సెప్ట్ డ్రిఫ్ట్ (Concept Drift):**
>   ఒక బ్యాంక్ లో సాధారణ రోజుల్లో రాత్రి 2 గంటలకు వరుసగా 10 ఆన్‌లైన్ షాపింగ్ లావాదేవీలు జరిగితే దాన్ని 99% మోసం (Fraud) అని మోడల్ నిర్ధారించేది.
>   కానీ అకస్మాత్తుగా **దీపావళి సేల్ (లేదా Black Friday)** వచ్చింది. ప్రజలంతా రాత్రి 2 గంటలకే మేల్కొని భారీగా షాపింగ్ చేస్తున్నారు. ఇప్పుడు అది మోసం కాదు, నిజమైన కస్టమర్లే కొంటున్నారు!
>   ఇక్కడ ఇన్పుట్ మరియు అవుట్‌పుట్ మధ్య ఉండే సంబంధమే మారిపోయింది ($P(Y|X)$). పాత మోడల్ అన్ని నిజమైన లావాదేవీలను బ్లాక్ చేసి బ్యాంకుకి కోట్ల నష్టం తెస్తుంది!

## 5. కోడింగ్ వాక్‌త్రూ: Python లో KS-Test & PSI డ్రిఫ్ట్ డిటెక్టర్

కింది పైథాన్ కోడ్ ద్వారా ప్రొడక్షన్ లో వస్తున్న కొత్త డేటాను, పాత ట్రైనింగ్ డేటాతో పోల్చి **KS-Test** మరియు **PSI** ని ఎలా లెక్కించవచ్చో పరిశీలిద్దాం:

```python
# drift_detector.py
import numpy as np
from scipy import stats

def calculate_psi(baseline: np.ndarray, current: np.ndarray, buckets: int = 10) -> float:
    """
    Population Stability Index (PSI) లెక్కిస్తుంది:
    PSI < 0.1   -> ఎటువంటి డ్రిఫ్ట్ లేదు (Safe)
    0.1 - 0.2   -> స్వల్ప మార్పు (Warning)
    PSI >= 0.2  -> తీవ్రమైన డ్రిఫ్ట్! వెంటనే రీట్రైనింగ్ చేయాలి (Action Needed)
    """
    percentiles = np.linspace(0, 100, buckets + 1)
    bucket_edges = np.percentile(baseline, percentiles)
    bucket_edges[0] -= 1e-5
    bucket_edges[-1] += 1e-5

    base_counts, _ = np.histogram(baseline, bins=bucket_edges)
    curr_counts, _ = np.histogram(current, bins=bucket_edges)

    # శాతాల్లోకి మార్చడం (Laplace smoothing తో డివైడ్ బై జీరో రాకుండా)
    base_pct = (base_counts + 1e-4) / len(baseline)
    curr_pct = (curr_counts + 1e-4) / len(current)

    psi_val = np.sum((curr_pct - base_pct) * np.log(curr_pct / base_pct))
    return float(psi_val)

class DriftMonitoringEngine:
    def evaluate_feature(self, name: str, train_data: np.ndarray, live_data: np.ndarray):
        # 1. Kolmogorov-Smirnov (KS) Test
        ks_stat, p_value = stats.ks_2samp(train_data, live_data)
        
        # 2. PSI స్కోరు
        psi_score = calculate_psi(train_data, live_data)

        # తీర్పు: P-value < 0.05 మరియు PSI > 0.2 ఉంటే డ్రిఫ్ట్ ఉన్నట్లు
        has_drift = (p_value < 0.05) and (psi_score >= 0.2)

        return {
            "feature": name,
            "p_value": round(p_value, 5),
            "psi_score": round(psi_score, 4),
            "drift_detected": has_drift,
            "status": "🚨 CRITICAL" if psi_score >= 0.2 else ("⚠️ WARNING" if psi_score >= 0.1 else "✅ STABLE")
        }

if __name__ == "__main__":
    np.random.seed(42)

    # బేస్‌లైన్ ట్రైనింగ్ డేటా: కస్టమర్ వయస్సు (సగటు: 40 సంవత్సరాలు)
    train_ages = np.random.normal(loc=40.0, scale=8.0, size=2000)

    # టెస్ట్ 1: సాధారణ లైవ్ ట్రాఫిక్ (సగటు: 40.5 సంవత్సరాలు)
    normal_traffic = np.random.normal(loc=40.5, scale=8.1, size=1000)

    # టెస్ట్ 2: భారీ క్యాంపెయిన్ వల్ల వచ్చిన యువకుల డేటా (సగటు: 21 సంవత్సరాలు)
    drifted_traffic = np.random.normal(loc=21.0, scale=3.5, size=1000)

    engine = DriftMonitoringEngine()

    print("--- 1. సాధారణ లైవ్ ట్రాఫిక్ పరిశీలన ---")
    res1 = engine.evaluate_feature("Customer_Age", train_ages, normal_traffic)
    print(f"PSI స్కోరు: {res1['psi_score']} | స్టేటస్: {res1['status']} | డ్రిఫ్ట్: {res1['drift_detected']}")

    print("\n--- 2. తీవ్రమైన మార్పు వచ్చిన లైవ్ ట్రాఫిక్ పరిశీలన ---")
    res2 = engine.evaluate_feature("Customer_Age", train_ages, drifted_traffic)
    print(f"PSI స్కోరు: {res2['psi_score']} | స్టేటస్: {res2['status']} | డ్రిఫ్ట్: {res2['drift_detected']}")

    if res2["drift_detected"]:
        print("\n📢 [హెచ్చరిక]: డేటా డిస్ట్రిబ్యూషన్ మారింది! CI/CD లో ఆటోమేటిక్ రీట్రైనింగ్ జాబ్ ని రన్ చేస్తున్నాం...")
```

```python
critical_count = sum(1 for f in features_status if f["status"] == "CRITICAL")

if critical_count >= 2:
    print(f"🚨 అలర్ట్: {critical_count} ఫీచర్లు డ్రిఫ్ట్ అయ్యాయి. వెంటనే రీట్రైనింగ్ ప్రారంభించండి!")
else:
    print("✅ సిస్టమ్ సాధారణ స్థితిలో ఉంది.")
```

## 8. టాప్ 3 ఇంటర్వ్యూ ప్రశ్నలు & సమాధానాలు

### Q1: Data Drift కి మరియు Concept Drift కి తేడా ఏమిటి?
**సమాధానం:**
- **Data Drift (Covariate Shift):** ఇన్పుట్ ఫీచర్ల డిస్ట్రిబ్యూషన్ $P(X)$ మారుతుంది, కానీ ఫీచర్లకి మరియు అవుట్‌పుట్ కి మధ్య ఉన్న సంబంధం మారదు (ఉదా: యాప్ ని వాడే వారి వయస్సు మారడం).
- **Concept Drift:** ఇన్పుట్ ఫీచర్లకి మరియు టార్గెట్ అవుట్‌పుట్ కి మధ్య ఉండే సంబంధమే మారిపోతుంది $P(Y|X)$ (ఉదా: ద్రవ్యోల్బణం పెరగడం వల్ల కస్టమర్ల కొనుగోలు ప్రవర్తన మారడం).

### Q2: ప్రొడక్షన్ లో వెంటనే గ్రౌండ్ ట్రూత్ (Ground Truth) లేబుల్స్ దొరకనప్పుడు మోడల్ ని ఎలా మానిటర్ చేస్తారు?
**సమాధానం:**
లోన్ ఎగ్గొట్టారా లేదా అనేది 2 ఏళ్ల తర్వాత తెలుస్తుంది, మోసం జరిగిందా లేదా అనేది నెల రోజుల తర్వాత తెలుస్తుంది. కాబట్టి ప్రొడక్షన్ లో రియల్ టైమ్ లేబుల్స్ వెంటనే రావు. అందుకని మనం ప్రాక్సీ మెట్రిక్స్ ద్వారా మానిటర్ చేస్తాం:
1. **Input Feature Drift:** ఇన్పుట్ ఫీచర్లు పాత డేటా లాగే ఉన్నాయా అని KS-Test మరియు PSI లెక్కిస్తాం.
2. **Prediction Distribution Drift:** మోడల్ ఇచ్చే ప్రాబబిలిటీలలో అకస్మాత్తుగా ఏమైనా తీవ్రమైన మార్పులు వచ్చాయా అని చూస్తాం.
3. **Data Quality Checks:** నల్ విలువలు, తప్పుడు కాలమ్ పేర్లు వస్తున్నాయేమో పర్యవేక్షిస్తాం.

### Q3: Population Stability Index (PSI) థ్రెషోల్డ్స్ ఎలా ఉంటాయి?
**సమాధానం:**
- **PSI < 0.1:** పాపులేషన్ స్థిరంగా ఉంది (No Drift).
- **0.1 $\le$ PSI < 0.2:** స్వల్ప మార్పు ఉంది, నిరంతరం గమనించాలి (Moderate Shift).
- **PSI $\ge$ 0.2:** తీవ్రమైన మార్పు వచ్చింది! మోడల్ ఖచ్చితత్వం పడిపోయే ప్రమాదం ఉంది, వెంటనే కొత్త డేటాతో మోడల్ ని రీట్రైన్ చేయాలి.
