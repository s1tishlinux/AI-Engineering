# డే 08 (Day 08): మాడ్యూల్స్, ప్యాకేజీలు & వర్చువల్ ఎన్విరాన్‌మెంట్స్ (Modules & Packages)

## 🎯 ఈ సెషన్ లక్ష్యాలు (Learning Objectives)
ఈ క్లాస్ పూర్తయ్యేసరికి మీరు క్రింది అంశాలను చాలా స్పష్టంగా అర్థం చేసుకుంటారు:
1. స్క్రిప్ట్, మాడ్యూల్ (`.py` ఫైల్) మరియు ప్యాకేజీ (`__init__.py` ఉన్న ఫోల్డర్) ల మధ్య తేడా.
2. పైథాన్ ఇంపోర్ట్స్ ఎలా పనిచేస్తాయి: `sys.path`, అబ్సల్యూట్ vs రిలేటివ్ ఇంపోర్ట్స్.
3. చాలా ఇంపార్టెంట్ కండిషన్: `if __name__ == "__main__":` అసలు రహస్యం.
4. ప్రాజెక్టులకు ప్రత్యేక గదులు: `venv` (వర్చువల్ ఎన్విరాన్‌మెంట్స్) ఎందుకు తప్పనిసరి?
5. `requirements.txt` ద్వారా డిపెండెన్సీలను మేనేజ్ చేయడం.

## 1. వర్చువల్ ఎన్విరాన్‌మెంట్స్ ఎందుకు అవసరం? (The "Why")

మీ ల్యాప్‌టాప్‌లో రెండు ప్రాజెక్టులు చేస్తున్నారని అనుకుందాం:
- **ప్రాజెక్ట్ A (2024 లో చేసిన పాత ప్రాజెక్ట్):** దీనికి `langchain==0.1.0` వెర్షన్ కావాలి.
- **ప్రాజెక్ట్ B (నేటి ఆధునిక 2026 ప్రాజెక్ట్):** దీనికి సరికొత్త `langchain==0.3.5` వెర్షన్ కావాలి.

మీరు మీ కంప్యూటర్‌లో గ్లోబల్‌గా `pip install langchain` కొడితే, కొత్త వెర్షన్ వచ్చి పాత వెర్షన్‌ని ఓవర్‌రైట్ చేస్తుంది. దాంతో **ప్రాజెక్ట్ A క్రాష్ అయిపోతుంది!**
దీనిని నివారించడానికి ప్రతి ప్రాజెక్టుకి ఒక ప్రత్యేకమైన **వర్చువల్ ఎన్విరాన్‌మెంట్ (ఐసోలేటెడ్ శాండ్‌బాక్స్ ఫోల్డర్)** ని క్రియేట్ చేస్తాం.

## 2. మాడ్యూల్ vs ప్యాకేజీ అంటే ఏమిటి? (Modules vs Packages)

- **మాడ్యూల్ (Module):** వేరియబుల్స్, ఫంక్షన్లు లేదా క్లాసులతో కూడిన ఏదైనా ఒకే ఒక పైథాన్ ఫైల్ (ఉదా: `data_cleaner.py`).
- **ప్యాకేజీ (Package):** ఒకటి కంటే ఎక్కువ మాడ్యూల్స్ మరియు ఒక `__init__.py` ఫైల్ ఉన్న డైరెక్టరీ (ఫోల్డర్).

### స్టాండర్డ్ కంపెనీ ప్రాజెక్ట్ ఫోల్డర్ స్ట్రక్చర్:
```text
my_ai_app/
│
├── .venv/                   # వర్చువల్ ఎన్విరాన్‌మెంట్ (దీన్ని Git లోకి పంపకూడదు!)
├── requirements.txt         # ప్రాజెక్ట్‌కి కావాల్సిన లైబ్రరీల లిస్ట్
├── main.py                  # అప్లికేషన్ ప్రారంభమయ్యే మెయిన్ ఫైల్
│
└── core/                    # ప్యాకేజీ ఫోల్డర్
    ├── __init__.py          # ఇది ఒక ప్యాకేజీ అని పైథాన్‌కి తెలియజేసే ఫైల్
    ├── model_loader.py      # మాడ్యూల్ ఫైల్
    └── token_counter.py     # మాడ్యూల్ ఫైల్
```

## 3. `if __name__ == "__main__":` వెనుక ఉన్న మ్యాజిక్

మనం టెర్మినల్ నుండి నేరుగా ఒక ఫైల్‌ని రన్ చేసినప్పుడు (`python main.py`), పైథాన్ ఆ ఫైల్ యొక్క అంతర్గత వేరియబుల్‌కి ఈ విలువను ఇస్తుంది:
`__name__ = "__main__"`

కానీ వేరే ఫైల్ నుండి ఆ మాడ్యూల్‌ని ఇంపోర్ట్ చేసుకున్నప్పుడు (`import main`), పైథాన్ దాని పేరును ఆ ఫైల్ పేరుగా మారుస్తుంది:
`__name__ = "main"`

```python
# math_utils.py

def add(a, b):
    return a + b

# ఈ బ్లాక్ కేవలం 'python math_utils.py' అని నేరుగా రన్ చేసినప్పుడు మాత్రమే నడుస్తుంది.
# వేరే ఫైల్ నుండి దీన్ని 'import' చేసుకున్నప్పుడు ఇక్కడున్న కోడ్ రన్ అవ్వదు!
if __name__ == "__main__":
    print("math_utils ఫంక్షన్లను లోకల్‌గా టెస్ట్ చేస్తున్నాం...")
    assert add(2, 3) == 5
    print("యూనిట్ టెస్టులన్నీ పాస్ అయ్యాయి!")
```

## 4. వర్చువల్ ఎన్విరాన్‌మెంట్ (`venv`) వాడే విధానం

### స్టెప్ 1: కొత్త ఎన్విరాన్‌మెంట్ తయారు చేయడం
ప్రాజెక్ట్ ఫోల్డర్ టెర్మినల్‌లో ఇలా టైప్ చేయండి:
```bash
# Mac / Linux లో:
python3 -m venv .venv

# Windows లో:
python -m venv .venv
```

### స్టెప్ 2: ఎన్విరాన్‌మెంట్‌ని యాక్టివేట్ చేయడం
```bash
# Mac / Linux లో:
source .venv/bin/activate

# Windows (Command Prompt) లో:
.venv\Scripts\activate.bat

# Windows (PowerShell) లో:
.venv\Scripts\Activate.ps1
```
*(ఇప్పుడు మీ టెర్మినల్ లైన్ ముందు `(.venv)` అని కనిపిస్తుంది! అంటే మీరు సేఫ్ జోన్‌లో ఉన్నారు.)*

### స్టెప్ 3: లైబ్రరీలు ఇన్‌స్టాల్ చేయడం & ఫ్రీజ్ చేయడం
```bash
# మన ప్రాజెక్ట్‌కి కావాల్సిన లైబ్రరీలు వేసుకోవడం
pip install pydantic httpx python-dotenv

# ప్రాజెక్ట్‌కి ఏయే వెర్షన్లు వాడామో requirements.txt లో సేవ్ చేయడం
pip freeze > requirements.txt
```

### స్టెప్ 4: పని పూర్తయ్యాక బయటకు రావడం
```bash
deactivate
```

## 5. అబ్సల్యూట్ vs రిలేటివ్ ఇంపోర్ట్స్ (Imports)

```python
# core/token_counter.py లోపల రాస్తున్నాం అనుకుందాం:

# 1. అబ్సల్యూట్ ఇంపోర్ట్ (Absolute Import - ఎల్లప్పుడూ ఇదే రికమండెడ్)
from core.model_loader import get_active_model

# 2. రిలేటివ్ ఇంపోర్ట్ (చుక్కలు వాడటం: . అంటే ప్రస్తుత ఫోల్డర్, .. అంటే పైన ఉన్న ఫోల్డర్)
from .model_loader import get_active_model  # అదే ఫోల్డర్ లోని ఫైల్
from ..config import APP_VERSION           # ఒక ఫోల్డర్ పైన ఉన్న ఫైల్
```

## 6. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **సిస్టమ్ లైబ్రరీల పేర్లతో ఫైల్స్ సేవ్ చేయడం:**
   - ⚠️ **అత్యంత భయంకరమైన తప్పు:** మీ ఫైల్‌కి `math.py`, `random.py` లేదా `json.py` అని పేరు పెట్టకండి! అలా పెడితే పైథాన్ ఒరిజినల్ మాడ్యూల్ బదులు మీ ఫైల్‌ని ఇంపోర్ట్ చేసుకుని కోడ్ మొత్తం క్రాష్ అవుతుంది.
2. **`.venv` ఫోల్డర్‌ని GitHub లోకి పుష్ చేయడం:**
   - ఎప్పుడూ వర్చువల్ ఎన్విరాన్‌మెంట్‌ని గిట్‌హబ్‌కి పంపకూడదు. దాన్ని `.gitignore` లో పెట్టాలి. కేవలం `requirements.txt` మాత్రమే పంపాలి.
3. **సర్క్యులర్ ఇంపోర్ట్స్ (Circular Imports):**
   - ఫైల్ A ఫైల్ B ని ఇంపోర్ట్ చేసుకోవడం, అదే సమయంలో ఫైల్ B కూడా ఫైల్ A ని ఇంపోర్ట్ చేసుకోవడం వల్ల `ImportError` వస్తుంది.

## 7. ప్రాక్టీస్ ల్యాబ్ (Daily Hands-On Lab)

### 🧪 టాస్క్: మోడ్యులర్ కాన్ఫిగరేషన్ ప్యాకేజీ (Config & Secrets)
**సన్నివేశం:** మీ AI ప్రాజెక్ట్‌కి అవసరమైన ఎన్విరాన్‌మెంట్ వేరియబుల్స్ (API Keys) ను లోడ్ చేసి, సీక్రెట్ కీలను మాస్క్ చేసి భద్రపరిచే ఒక మాడ్యూల్ రాయండి.

```python
# ==========================================
# Day 8 Lab: మోడ్యులర్ కాన్ఫిగరేషన్ మేనేజర్
# ==========================================
import os
import sys

class AppConfig:
    def __init__(self):
        # ఎన్విరాన్‌మెంట్ నుండి కీలను తీసుకుంటుంది
        self.app_env = os.getenv("APP_ENV", "development")
        self.api_key = os.getenv("GEMINI_API_KEY", "dummy-default-key-xyz123")
        self.debug_mode = self.app_env == "development"

    def get_masked_key(self) -> str:
        """రహస్య API కీ బయటకు కనబడకుండా మాస్క్ చేస్తుంది."""
        if len(self.api_key) <= 6:
            return "******"
        return f"{self.api_key[:4]}...{self.api_key[-3:]}"

    def display_environment(self):
        print("="*45)
        print(f"🚀 అప్లికేషన్ ఎన్విరాన్‌మెంట్ : {self.app_env.upper()}")
        print(f"🛠️ డీబగ్ మోడ్ ఆన్‌లో ఉందా?   : {self.debug_mode}")
        print(f"🔑 యాక్టివ్ API కీ (రక్షితం)  : {self.get_masked_key()}")
        print(f"🐍 పైథాన్ పాత్              : {sys.executable}")
        print("="*45)

if __name__ == "__main__":
    print("కాన్ఫిగరేషన్ మాడ్యూల్‌ని నేరుగా టెస్ట్ చేస్తున్నాం...")
    config = AppConfig()
    config.display_environment()
```

## 8. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: ఒక డైరెక్టరీలో `__init__.py` ఫైల్ ఉద్దేశం ఏమిటి?**
   - **సమాధానం:** `__init__.py` ఉన్న ఫోల్డర్‌ను పైథాన్ ఒక ప్యాకేజీగా గుర్తిస్తుంది. ఆ ప్యాకేజీ నుండి ఏయే మాడ్యూల్స్ బయటకు ఎక్స్‌పోర్ట్ కావాలో (`__all__`) నిర్ణయించడానికి మరియు ప్యాకేజీ ఇనీషియలైజేషన్ కోడ్ రన్ చేయడానికి ఇది ఉపయోగపడుతుంది.
2. **ప్రశ్న: పైథాన్‌లో `sys.path` లో ఏముంటుంది?**
   - **సమాధానం:** మనం `import` చేసినప్పుడు పైథాన్ ఏయే డైరెక్టరీలలో మాడ్యూల్స్ కోసం వెతకాలో చెప్పే ఫోల్డర్ల లిస్ట్ `sys.path`. ఇందులో ప్రస్తుత ఫైల్ ఉన్న ఫోల్డర్, పైథాన్ స్టాండర్డ్ లైబ్రరీ పాత్‌లు మరియు వర్చువల్ ఎన్విరాన్‌మెంట్‌లోని సైట్-ప్యాకేజీలు (site-packages) ఉంటాయి.
3. **ప్రశ్న: వర్చువల్ ఎన్విరాన్‌మెంట్ ఫోల్డర్‌ను Git రిపోజిటరీకి ఎందుకు కమిట్ చేయకూడదు?**
   - **సమాధానం:** వర్చువల్ ఎన్విరాన్‌మెంట్ అనేది కంప్యూటర్ ఆపరేటింగ్ సిస్టమ్ (Mac/Windows/Linux) మరియు ఆర్కిటెక్చర్‌పై ఆధారపడి ఉంటుంది. అది వేలాది బైనరీ ఫైల్స్‌తో చాలా పెద్దదిగా ఉంటుంది. కాబట్టి దానికి బదులుగా `requirements.txt` మాత్రమే కమిట్ చేస్తాం. ఇతర డెవలపర్లు `pip install -r requirements.txt` కొట్టి వారి సిస్టమ్‌లో అదే వాతావరణాన్ని రీక్రియేట్ చేసుకుంటారు.
