## 1. AI మరియు బిగ్ డేటాలో జెనరేటర్ల ప్రాముఖ్యత (The "Why")

ఒక 10 GB టెక్స్ట్ ఫైల్‌ని మోడల్ ట్రైనింగ్ కోసం పైథాన్‌లోకి లోడ్ చేస్తున్నారని అనుకుందాం.
- మీరు `file.readlines()` వాడితే, మొత్తం 10 GB ని ఒకేసారి ల్యాప్‌టాప్ RAM లోకి లాగడానికి ప్రయత్నిస్తుంది. దాంతో మీ ల్యాప్‌టాప్ వెంటనే హాంగ్ అయిపోయి **`Out of Memory (OOM)`** ఎర్రర్‌తో క్రాష్ అవుతుంది!
- అదే **జెనరేటర్ (`yield`)** వాడితే, పైథాన్ **ఒక్కో లైన్‌ను మాత్రమే** RAM లోకి తెస్తుంది, ప్రాసెస్ చేసి పంపేస్తుంది. మొత్తం వాడే మెమొరీ కేవలం **50 KB లోపే!**

## 2. స్టాక్స్ & క్యూలు (Stacks & Queues)

### A. స్టాక్ (LIFO: Last In, First Out - చివరిగా వచ్చినది మొదట వెళ్తుంది)
- **ఉదాహరణ:** హోటల్‌లో ఒకదానిపై ఒకటి పేర్చిన ప్లేట్ల దొంతర. చివరగా పెట్టిన ప్లేట్‌నే మొదట తీసుకుంటారు.
- **ఎక్కడ వాడతారు?:** బ్రౌజర్‌లో వెనక్కి వెళ్లే 'Back Button', టెక్స్ట్ ఎడిటర్‌లో 'Undo' ఆప్షన్.

```python
# సాధారణ పైథాన్ లిస్ట్‌ని .append() మరియు .pop() తో స్టాక్‌లా వాడవచ్చు
browser_history = []

# పేజీలు ఓపెన్ చేయడం (Push)
browser_history.append("google.com")
browser_history.append("github.com")
browser_history.append("openai.com")

# వెనక్కి వెళ్లడం (Pop)
current_page = browser_history.pop()
print("వెనక్కి వచ్చిన పేజీ:", current_page)  # openai.com
print("ప్రస్తుతం ఉన్న పేజీ :", browser_history[-1])   # github.com
```

### B. క్యూ (FIFO: First In, First Out - మొదట వచ్చిన వారికి మొదటి ప్రాధాన్యత)
- **ఉదాహరణ:** సినిమా థియేటర్ టికెట్ కౌంటర్ ముందు నిలబడిన క్యూ.
- **ఎక్కడ వాడతారు?:** కస్టమర్ సపోర్ట్ టికెట్లు, మెసేజ్ క్యూలు (Kafka, RabbitMQ, Celery).
- ⚠️ **ముఖ్య గమనిక:** క్యూ కోసం ఎప్పుడూ `list.pop(0)` వాడకూడదు! ఎందుకంటే మొదటి ఎలిమెంట్ తీసేసినప్పుడు మిగిలిన అన్ని ఎలిమెంట్లను పైథాన్ మెమొరీలో ముందుకు జరపాల్సి వస్తుంది ($O(n)$ స్లో). ఎల్లప్పుడూ **`collections.deque`** నే వాడాలి ($O(1)$ సూపర్ ఫాస్ట్).

```python
from collections import deque

request_queue = deque()

# టికెట్లను క్యూలో చేర్చడం
request_queue.append("టికెట్ #101: పాస్‌వర్డ్ రీసెట్")
request_queue.append("టికెట్ #102: రీఫండ్ రిక్వెస్ట్")
request_queue.append("టికెట్ #103: API సర్వర్ డౌన్")

# మొదట వచ్చిన టికెట్‌ని ప్రాసెస్ చేయడం (O(1) సమయం)
served = request_queue.popleft()
print(f"ప్రాసెస్ చేసిన టికెట్: {served}")  # టికెట్ #101
print(f"తదుపరి లైన్‌లో ఉన్నది: {request_queue[0]}")
```

## 3. జెనరేటర్లు & `yield` (Generators)

ఫంక్షన్‌లో `return` బదులుగా `yield` వాడినప్పుడు, ఆ ఫంక్షన్ ఎగ్జిక్యూషన్‌ను తాత్కాలికంగా ఆపి విలువను బయటకు ఇస్తుంది. తర్వాతి సారి పిలిచినప్పుడు **ఎక్కడ ఆగిందో అక్కడి నుండే మళ్లీ మొదలవుతుంది!**

```python
# ఒక మిలియన్ సెన్సార్ రీడింగ్‌లను మెమొరీ వాడకుండా ఒక్కొక్కటిగా ఇచ్చే జెనరేటర్:
def stream_sensor_readings(limit: int):
    val = 1
    while val <= limit:
        # yield మెమొరీని ఖర్చు చేయకుండా ప్రస్తుత విలువను మాత్రమే ఇస్తుంది
        yield f"సెన్సార్ పింగ్ #{val} | ఉష్ణోగ్రత: {20 + val * 0.5}°C"
        val += 1

# జెనరేటర్ ఆబ్జెక్ట్ క్రియేట్ చేశాం (ఇది RAM ని అసలు వాడదు)
sensor_stream = stream_sensor_readings(1000000)
print("రకం:", type(sensor_stream))

# కావాల్సినప్పుడు ఒక్కొక్కటిగా తీసుకోవడం (Lazy Evaluation):
print(next(sensor_stream))
print(next(sensor_stream))
```

## 4. బిగ్-ఓ కాంప్లెక్సిటీ సులభంగా (Big-O Complexity)

డేటా పెరిగేకొద్దీ మీ ప్రోగ్రామ్ రన్ కావడానికి ఎంత సమయం పడుతుందో చెప్పే కొలమానమే బిగ్-ఓ (Big-O):

| బిగ్-ఓ సింబల్ | పేరు | ఉదాహరణ | వేగం |
| :--- | :--- | :--- | :--- |
| **$O(1)$** | కాన్స్టంట్ టైమ్ | సెట్ లేదా డిక్షనరీలో కీ వెతకడం | క్షణంలో (0.001 ms) |
| **$O(\log n)$** | లాగరిథమిక్ | సార్ట్ చేసిన డేటాలో బైనరీ సెర్చ్ చేయడం | సూపర్ ఫాస్ట్ |
| **$O(n)$** | లీనియర్ | సాధారణ లిస్ట్‌లో ఒక ఎలిమెంట్‌ని వెతకడం | సాధారణ వేగం |
| **$O(n \log n)$** | లీనియరిథమిక్ | పైథాన్ లోపల ఉండే Timsort (`list.sort()`) | సార్టింగ్‌కి స్టాండర్డ్ |
| **$O(n^2)$** | క్వాడ్రాటిక్ | ఒక లూప్ లోపల ఇంకో లూప్ రాయడం | చాలా స్లో (డేటా ఎక్కువైతే క్రాష్) |

## 5. బైనరీ సెర్చ్ అల్గారిథమ్ ($O(\log n)$)

డేటా ఇప్పటికే ఒక క్రమపద్ధతిలో (Sorted) అమర్చబడి ఉంటే, 10 లక్షల నెంబర్లను ఒక్కొక్కటిగా చూడాల్సిన పనిలేదు. మధ్యలో ఉన్న నెంబర్ చెక్ చేసి, సగం భాగాన్ని పూర్తిగా వదిలేయవచ్చు!

```python
def binary_search(sorted_list: list[int], target: int) -> int:
    """సార్ట్ చేసిన లిస్ట్‌లో బైనరీ సెర్చ్ చేస్తుంది. O(log n) వేగంతో పనిచేస్తుంది."""
    low = 0
    high = len(sorted_list) - 1

    while low <= high:
        mid = (low + high) // 2
        mid_val = sorted_list[mid]

        if mid_val == target:
            return mid  # నెంబర్ దొరికింది
        elif mid_val < target:
            low = mid + 1  # ఎడమ వైపు భాగాన్ని వదిలేయ్
        else:
            high = mid - 1  # కుడి వైపు భాగాన్ని వదిలేయ్

    return -1

# 10 లక్షల సరి సంఖ్యల లిస్ట్:
large_sorted_data = list(range(0, 1000000, 2))
target_num = 754320

index = binary_search(large_sorted_data, target_num)
print(f"వెతికిన నెంబర్ {target_num} ఇండెక్స్ {index} వద్ద ఉంది!")  # 10 లక్షల రికార్డులను కేవలం ~20 స్టెప్పుల్లోనే కనుగొంది!
```

## 6. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **జెనరేటర్‌ని నేరుగా లిస్ట్‌గా మార్చడం:**
   - `list(my_generator)` అని రాస్తే జెనరేటర్ యొక్క అసలు ఉద్దేశమే దెబ్బతింటుంది. అన్ని లక్షల రికార్డులు ఒక్కసారిగా RAM లోకి వచ్చేసి మెమొరీ నిండిపోతుంది.
2. **పూర్తయిపోయిన జెనరేటర్‌ని మళ్లీ వాడటానికి ప్రయత్నించడం:**
   - జెనరేటర్ ఒక్కసారే చివరి వరకు రన్ అవుతుంది. మళ్లీ వాడాలంటే కొత్త జెనరేటర్ ఆబ్జెక్ట్‌ను క్రియేట్ చేయాలి.
3. **క్యూ కోసం `list.pop(0)` వాడటం:**
   - లిస్ట్‌లో మొదటి ఎలిమెంట్‌ని తీస్తే మిగిలిన లక్షల ఎలిమెంట్లను కంప్యూటర్ ముందుకు జరపాల్సి వస్తుంది. క్యూ కోసం ఎల్లప్పుడూ `collections.deque` మాత్రమే వాడాలి.

## 7. మాడ్యూల్ 02 క్యాప్‌స్టోన్ మినీ ప్రాజెక్ట్: రియల్-టైమ్ లాగ్ స్ట్రీమింగ్ ఇంజిన్

ఈ ప్రాజెక్ట్‌లో OOP, క్యూలు (`deque`), జెనరేటర్లు (`yield`) మరియు బిగ్-ఓ ఆప్టిమైజేషన్ అన్నీ కలిపి ఒక లైవ్ సర్వర్ లాగ్ సిస్టమ్ తయారు చేయబడింది:

```python
# =================================================================
# Module 02 Capstone: రియల్-టైమ్ లాగ్ స్ట్రీమింగ్ & అలర్ట్ ఇంజిన్
# =================================================================
from collections import deque
from typing import Generator
import time

class LogRecord:
    def __init__(self, log_id: int, level: str, message: str):
        self.log_id = log_id
        self.level = level
        self.message = message

    def __repr__(self):
        return f"[{self.level}] #{self.log_id:04d}: {self.message}"

class LogStreamSimulator:
    """జెనరేటర్లు వాడి మెమొరీ లేకుండా వేలాది లాగ్స్‌ని స్ట్రీమ్ చేస్తుంది."""
    @staticmethod
    def generate_logs(count: int) -> Generator[LogRecord, None, None]:
        levels = ["INFO", "DEBUG", "INFO", "WARNING", "ERROR"]
        messages = [
            "యూజర్ లాగిన్ విజయవంతమైంది",
            "Redis కాష్ నుండి డేటా తెస్తున్నాం",
            "డేటాబేస్ కనెక్షన్ ఏర్పడింది",
            "సర్వర్ CPU వేడెక్కుతోంది",
            "పేమెంట్ గేట్‌వే టైమ్-అవుట్ అయింది"
        ]
        for i in range(1, count + 1):
            lvl = levels[i % len(levels)]
            msg = messages[i % len(messages)]
            yield LogRecord(log_id=i, level=lvl, message=msg)

class RealtimeLogMonitor:
    def __init__(self, buffer_size: int = 5):
        # స్లైడింగ్ విండో: కేవలం లేటెస్ట్ 5 లాగ్స్ మాత్రమే మెమొరీలో ఉంచుతుంది
        self.sliding_buffer = deque(maxlen=buffer_size)
        self.error_count = 0

    def ingest_stream(self, log_generator: Generator[LogRecord, None, None]):
        print(f"📡 లైవ్ లాగ్ స్ట్రీమ్ ప్రారంభమైంది (బఫర్ సైజు: {self.sliding_buffer.maxlen})...\n")
        for log in log_generator:
            self.sliding_buffer.append(log)
            if log.level == "ERROR":
                self.error_count += 1
                print(f"🚨 అత్యవసర అలర్ట్ (CRITICAL): {log}")

    def display_latest_state(self):
        print("\n" + "="*50)
        print("📊 చివరిగా వచ్చిన లాగ్స్ (SLIDING WINDOW BUFFER)")
        print("="*50)
        for log in self.sliding_buffer:
            print("  ", log)
        print(f"\nగుర్తించిన మొత్తం తీవ్రమైన ఎర్రర్లు: {self.error_count}")
        print("="*50)

# ప్రాజెక్ట్‌ను రన్ చేద్దాం:
if __name__ == "__main__":
    stream = LogStreamSimulator.generate_logs(count=25)
    monitor = RealtimeLogMonitor(buffer_size=5)
    monitor.ingest_stream(stream)
    monitor.display_latest_state()
```

## 8. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: పైథాన్‌లో `return` మరియు `yield` మధ్య తేడా ఏమిటి?**
   - **సమాధానం:** `return` అనేది ఫంక్షన్‌ని పూర్తిగా ముగించి ఒక విలువను ఇచ్చి లోకల్ మెమొరీని నాశనం చేస్తుంది. `yield` అనేది ఫంక్షన్‌ను తాత్కాలికంగా ఆపి ప్రస్తుత విలువను బయటకు ఇస్తుంది మరియు ఫంక్షన్ స్థితిని (State) అలానే కాపాడుతుంది; తర్వాతి సారి `next()` అన్నప్పుడు అక్కడి నుంచే కొనసాగుతుంది.
2. **ప్రశ్న: క్యూ ఇంప్లిమెంట్ చేయడానికి లిస్ట్ కంటే `collections.deque` ఎందుకు మంచిది?**
   - **సమాధానం:** లిస్ట్‌లో మొదటి ఎలిమెంట్‌ని తీసివేస్తే (`list.pop(0)`), మిగిలిన అన్ని ఎలిమెంట్లను మెమొరీలో ముందుకు తరలించాల్సి వస్తుంది, దీనికి $O(n)$ సమయం పడుతుంది. కానీ `collections.deque` అనేది డబ్లీ-లింక్డ్ లిస్ట్ ఆధారంగా పనిచేస్తుంది, కాబట్టి ప్రారంభంలో మరియు చివరలో ఎలిమెంట్స్ చేర్చడానికి/తొలగించడానికి కేవలం $O(1)$ సమయం మాత్రమే తీసుకుంటుంది.
3. **ప్రశ్న: పైథాన్ లిస్ట్‌లో మరియు సెట్‌లో డేటా వెతకడానికి సగటున ఎంత సమయం పడుతుంది?**
   - **సమాధానం:** లిస్ట్‌లో డేటా వెతకడానికి లీనియర్ టైమ్ $O(n)$ పడుతుంది ఎందుకంటే ప్రతి ఎలిమెంట్‌ని లైన్‌గా చూసుకుంటూ వెళ్లాలి. సెట్‌లో డేటా వెతకడానికి సగటున కాన్స్టంట్ టైమ్ $O(1)$ మాత్రమే పడుతుంది ఎందుకంటే సెట్ అంతర్గతంగా హాష్ టేబుల్స్‌ను ఉపయోగిస్తుంది.
