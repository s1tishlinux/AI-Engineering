## 3. Google Gemini Python SDK Integration

Google's Gemini 1.5 family (Flash and Pro) offers native multimodal capabilities and industry-leading 1M–2M context windows.

```python
import os
from google import genai
from google.genai import types

# 1. Initialize Client (Automatically reads GEMINI_API_KEY from environment)
client = genai.Client()

# 2. Configure System Instructions & Generation Parameters
config = types.GenerateContentConfig(
    system_instruction="You are a Principal Software Architect. Give concise, actionable answers.",
    temperature=0.2,
    max_output_tokens=500
)

# 3. Single-Turn Generation
response = client.models.generate_content(
    model="gemini-1.5-flash",
    contents="Explain why connection pooling is essential in database design.",
    config=config
)

print("--- GEMINI RESPONSE ---")
print(response.text)

# Token Usage Tracking
if response.usage_metadata:
    print(f"\nPrompt Tokens: {response.usage_metadata.prompt_token_count}")
    print(f"Candidates Tokens: {response.usage_metadata.candidates_token_count}")
    print(f"Total Tokens: {response.usage_metadata.total_token_count}")
```

## 4. Real-Time Streaming Responses (Solving UI Latency)

If an LLM takes 6 seconds to write a 400-word response, making the user stare at a spinning loader for 6 seconds leads to bad user experience.
**Streaming yields tokens as they are generated by the GPU**, giving users instant perceived response times:

```python
import asyncio
from google import genai

client = genai.Client()

async def stream_ai_response(prompt: str):
    print("AI: ", end="", flush=True)
    
    # generate_content_stream streams chunks as they arrive!
    response_stream = client.models.generate_content_stream(
        model="gemini-1.5-flash",
        contents=prompt
    )

    for chunk in response_stream:
        print(chunk.text, end="", flush=True)
    print("\n")

# Run streaming demonstration
stream_ai_response("Write a 3-bullet summary of the benefits of microservices.")
```

## 5. Multi-Turn Chat Sessions (Maintaining Memory)

LLMs are fundamentally stateless. To have a conversation, the client must maintain and pass the entire history of turns back to the model:

```python
from google import genai

client = genai.Client()

# Chats maintain conversation history automatically
chat = client.chats.create(model="gemini-1.5-flash")

# Turn 1
resp1 = chat.send_message("Hi, my name is Arvind and I'm building an AI travel planner.")
print("Assistant:", resp1.text)

# Turn 2 (Model remembers Arvind!)
resp2 = chat.send_message("What was my name and what project am I working on?")
print("Assistant:", resp2.text)

# Inspect internal history
print(f"\nTotal messages in conversation history: {len(chat.get_history())}")
```

## 6. Token Tracking & Cost Calculation Engine

In enterprise environments, unexpected AI bills can cost thousands of dollars. You must track token consumption and convert it to currency:

```python
class TokenCostTracker:
    # Pricing per 1 Million tokens (Gemini 1.5 Flash standard tier)
    PRICE_INPUT_PER_1M_USD = 0.075
    PRICE_OUTPUT_PER_1M_USD = 0.300
    USD_TO_INR = 83.5

    @classmethod
    def calculate_cost(cls, prompt_tokens: int, completion_tokens: int) -> dict:
        cost_input_usd = (prompt_tokens / 1_000_000) * cls.PRICE_INPUT_PER_1M_USD
        cost_output_usd = (completion_tokens / 1_000_000) * cls.PRICE_OUTPUT_PER_1M_USD
        total_usd = cost_input_usd + cost_output_usd
        total_inr = total_usd * cls.USD_TO_INR

        return {
            "total_tokens": prompt_tokens + completion_tokens,
            "cost_usd": f"${total_usd:.6f}",
            "cost_inr": f"₹{total_inr:.4f}"
        }

metrics = TokenCostTracker.calculate_cost(prompt_tokens=1500, completion_tokens=450)
print("Cost Metrics for Request:", metrics)
```

## 7. Common Fresher Pitfalls

1. **Leaking API keys in Git commits**:
   - Always load from `os.getenv("GEMINI_API_KEY")`. If you accidentally push a key to GitHub, invalidate it immediately in the cloud console.
2. **Infinite conversation history accumulation**:
   - In chat sessions, if you append every user message indefinitely, the prompt grows to 50,000 tokens, making each subsequent turn progressively slower and more expensive! Implement a sliding-window trimmer to keep only the last $N$ turns.
3. **Not handling rate limit retries**:
   - When calling AI APIs in parallel, you *will* encounter `429 ResourceExhausted`. Always wrap calls in a retry loop with exponential backoff.

## 8. Daily Hands-On Lab

### 🧪 Exercise: Build a Resilient CLI AI Terminal Assistant
**Scenario**: Build an interactive terminal assistant that supports multi-turn memory, streams responses live to the console, calculates token costs, and handles network disconnections gracefully.

```python
# =========================================================
# Day 23 Lab: Resilient Streaming Terminal AI Copilot
# =========================================================
import os
import sys
import time
from google import genai
from google.genai import types

def start_terminal_copilot():
    api_key = os.getenv("GEMINI_API_KEY")
    if not api_key:
        print("❌ ERROR: Please set the GEMINI_API_KEY environment variable!")
        return

    client = genai.Client(api_key=api_key)
    chat = client.chats.create(
        model="gemini-1.5-flash",
        config=types.GenerateContentConfig(
            system_instruction="You are a helpful Python Pair Programmer. Be concise.",
            temperature=0.3
        )
    )

    print("="*55)
    print("🤖 TECHIN AI TERMINAL COPILOT (Type 'exit' to quit)")
    print("="*55)

    while True:
        try:
            user_input = input("\nYou > ").strip()
            if not user_input:
                continue
            if user_input.lower() in ["exit", "quit", "q"]:
                print("Exiting Copilot. Happy coding!")
                break

            print("\nCopilot > ", end="", flush=True)
            
            # Streaming response
            response_stream = chat.send_message_stream(user_input)
            for chunk in response_stream:
                print(chunk.text, end="", flush=True)
            print()

        except KeyboardInterrupt:
            print("\nSession interrupted by user.")
            break
        except Exception as e:
            print(f"\n⚠️ API Glitch occurred: {e}. Retrying in 2 seconds...")
            time.sleep(2)

if __name__ == "__main__":
    start_terminal_copilot()
```

## 9. Interview Quick-Fire Questions

1. **Q: Why are LLMs considered stateless and how do multi-turn chat sessions work?**
   - **Answer**: LLMs have no persistent internal memory between HTTP requests; each API call is evaluated independently. Multi-turn chat sessions work by having the client application maintain the chronological list of all previous user queries and model responses and resubmitting that entire conversation history as the context payload on every subsequent turn.
2. **Q: How does HTTP streaming (Server-Sent Events) work with LLMs?**
   - **Answer**: Instead of waiting for the model to finish generating all tokens and sending a single monolithic HTTP response, the server uses HTTP/1.1 chunked transfer encoding or Server-Sent Events (SSE). As the GPU generates each individual token, it immediately flushes it over the open TCP socket to the client, providing a fluid real-time typing animation.
3. **Q: What is the difference between Input Tokens and Output Tokens in API billing?**
   - **Answer**: **Input Tokens** (Prompt Tokens) are processed in parallel during the prefill phase by the model's self-attention matrix, which is computationally efficient. **Output Tokens** (Completion Tokens) must be generated sequentially one-by-one autoregressively, requiring repeated memory bandwidth access; consequently, providers charge 3x to 5x more per token for output than input.
