# డే 24 (Day 24): అడ్వాన్స్‌డ్ LLM సామర్థ్యాలు (Function Calling, Structured JSON & Multimodality)

## 🎯 ఈ సెషన్ లక్ష్యాలు (Learning Objectives)
ఈ క్లాస్ పూర్తయ్యేసరికి మీరు క్రింది అంశాలను చాలా స్పష్టంగా అర్థం చేసుకుంటారు:

3. నేటివ్ మల్టీమోడాలిటీ: బొమ్మలు (Images), ఆడియో మరియు PDF డాక్యుమెంట్లను AI కి పంపడం.

## 1. AI కి చేతులు మరియు కళ్ళు ఇవ్వడం! (The "Why")

ఒక సాధారణ LLM అనేది కేవలం గదిలో బంధించిన మెదడు లాంటిది:
- అది ఈరోజు స్టాక్ మార్కెట్ ధరను చూడలేదు, మీ కంపెనీ SQL డేటాబేస్‌ను చదవలేదు.
- ఒక ఇన్వాయిస్ ఫోటోను చూడలేదు లేదా వాయిస్ మెసేజ్‌ను వినలేదు.
- దాన్ని JSON ఫార్మాట్ అడిగితే కొన్నిసార్లు తప్పుడు బ్రాకెట్లతో డేటాబేస్‌ను క్రాష్ చేస్తుంది.

**అడ్వాన్స్‌డ్ ఫీచర్లు AI కి శక్తులు ఇస్తాయి:**
1. **చేతులు (Function Calling):** మన డేటాబేస్ క్వెరీలు రన్ చేయడం, ఈమెయిల్స్ పంపడం.
2. **కళ్ళు & చెవులు (Multimodality):** చార్టులు, ఫైల్స్, ఆడియోను నేరుగా అర్థం చేసుకోవడం.
3. **కచ్చితమైన నిర్మాణం (Pydantic Output):** ఏ చిన్న తప్పు లేకుండా ఎల్లప్పుడూ సరైన JSON డేటాను ఇవ్వడం.

## 2. Pydantic ద్వారా కచ్చితమైన JSON అవుట్‌పుట్

ప్రాంప్ట్‌లో *"దయచేసి JSON లో మాత్రమే సమాధానం రాయి"* అని అడిగినా 5% సమయాల్లో మోడల్ తప్పు ఫార్మాట్ ఇస్తుంది.
కానీ ఆధునిక SDK లలో **Schema-Constrained Decoding** ద్వారా 100% పక్కాగా JSON వచ్చేలా చేయవచ్చు:

```python
from google import genai
from google.genai import types
from pydantic import BaseModel, Field

# 1. Pydantic మోడల్ ద్వారా స్కీమా తయారు చేయడం
class JobCandidateProfile(BaseModel):
    full_name: str
    years_of_experience: float
    core_technical_skills: list[str]
    current_location: str
    suitable_for_senior_role: bool = Field(description="5 ఏళ్ల కంటే ఎక్కువ అనుభవం ఉంటే True")

# 2. జెమినిని ఆ స్కీమా ప్రకారం మాత్రమే సమాధానం ఇవ్వమని ఆదేశించడం
client = genai.Client()

resume_text = """
రాహుల్ స్వామినాథన్ బెంగళూరులో సీనియర్ డెవాప్స్ ఇంజనీర్‌గా పనిచేస్తున్నారు. 
అతనికి కుబెర్‌నెటీస్, గిట్‌హబ్ యాక్షన్స్ మరియు టెర్రాఫామ్‌లలో 7.5 సంవత్సరాల అనుభవం ఉంది.
"""

response = client.models.generate_content(
    model="gemini-1.5-flash",
    contents=f"ఈ రెజ్యూమె నుండి అభ్యర్థి వివరాలను సేకరించండి:\n{resume_text}",
    config=types.GenerateContentConfig(
        response_mime_type="application/json",
        response_schema=JobCandidateProfile
    )
)

print("--- 100% గ్యారెంటీ JSON అవుట్‌పుట్ ---")
print(response.text)

# ఎర్రర్ లేకుండా నేరుగా పైథాన్ ఆబ్జెక్ట్‌గా మార్చడం:
candidate = JobCandidateProfile.model_validate_json(response.text)
print(f"పేరు: {candidate.full_name} | సీనియర్ రోల్‌కి అర్హుడా?: {candidate.suitable_for_senior_role}")
```

## 3. టూల్ / ఫంక్షన్ కాలింగ్ ఎలా పనిచేస్తుంది? (Function Calling)

⚠️ **ఫ్రెషర్స్ చేసే పెద్ద పొరపాటు:**
చాలామంది AI నే స్వయంగా మన పైథాన్ కోడ్‌ను తన సర్వర్లలో రన్ చేస్తుంది అనుకుంటారు. అది తప్పు!
1. మనం రాసిన పైథాన్ ఫంక్షన్ల లిస్ట్ (పేరు, పారామీటర్లు, డాక్యుమెంటేషన్) ని మోడల్‌కి ఇస్తాం.
2. మోడల్ ప్రశ్నను చదివి: *"నేను సమాధానం చెప్పలేను కానీ మీరు `get_order_status(order_id=1001)` రన్ చేసి ఆ వివరాలు నాకు ఇవ్వండి"* అని అడుగుతుంది.
3. **మన పైథాన్ ప్రోగ్రామ్** ఆ ఫంక్షన్‌ని లోకల్‌గా రన్ చేసి వచ్చిన ఫలితాన్ని మళ్లీ AI కి ఇస్తుంది.
4. AI ఆ ఫలితాన్ని చదివి మనుషులకు అర్థమయ్యేలా అందంగా సమాధానం చెబుతుంది!

```python
from google import genai
from google.genai import types

# 1. మన సొంత పైథాన్ ఫంక్షన్
def get_order_delivery_status(order_id: int) -> dict:
    """ఆర్డర్ ఐడీ ఆధారంగా షిప్పింగ్ డెలివరీ స్థితిని తెలియజేస్తుంది."""
    MOCK_DB = {
        1001: {"status": "డెలివరీకి బయలుదేరింది", "లొకేషన్": "హైదరాబాద్ హబ్", "సమయం": "ఈరోజు సాయంత్రం 6 గంటలకు"},
        1002: {"status": "ప్రాసెసింగ్", "లొకేషన్": "ముంబై వేర్‌హౌస్", "సమయం": "రేపు"}
    }
    return MOCK_DB.get(order_id, {"status": "NOT_FOUND", "message": "ఈ ఆర్డర్ ఐడీ లేదు."})

# 2. జెమిని క్లయింట్‌కి ఈ టూల్‌ని అప్పగించడం
client = genai.Client()

chat = client.chats.create(
    model="gemini-1.5-flash",
    config=types.GenerateContentConfig(
        tools=[get_order_delivery_status],  # జెమిని ఆటోమేటిక్‌గా దీనిని అర్థం చేసుకుంటుంది
        temperature=0.0
    )
)

# 3. యూజర్ తన ఆర్డర్ గురించి అడగడం
response = chat.send_message("నా ఆర్డర్ నెంబర్ 1001 ప్రస్తుతం ఎక్కడుంది?")
print("AI అసిస్టెంట్:", response.text)
```

## 4. మల్టీమోడాలిటీ: బొమ్మలు & చార్టుల విశ్లేషణ (Vision)

జెమిని మోడల్స్ టెక్స్ట్‌తో పాటు ఫోటోలను మరియు డాక్యుమెంట్లను నేరుగా ఒకేసారి విశ్లేషించగలవు:

```python
from google import genai
from PIL import Image

client = genai.Client()

# లోకల్ ఫోటోను లోడ్ చేయడం
image = Image.open("sample_chart.png")

prompt = "ఈ ఫైనాన్షియల్ చార్ట్‌ను విశ్లేషించి, Q2 నుండి Q3 కి రెవెన్యూ ఎంత శాతం పెరిగిందో చెప్పు."

response = client.models.generate_content(
    model="gemini-1.5-flash",
    contents=[prompt, image]
)

print("విజన్ విశ్లేషణ:\n", response.text)
```

## 5. కాంటెక్స్ట్ కాషింగ్ (Context Caching - 75% ఖర్చు ఆదా)

మీ కంపెనీలో ఒక 500 పేజీల పాలసీ బుక్ ఉంది. రోజూ వందలాది మంది ఉద్యోగులు దాన్నుండి డౌట్లు అడుగుతుంటారు:
- పాత పద్ధతిలో: ప్రతి ప్రశ్నకీ ఆ 500 పేజీలను మళ్లీ మళ్లీ మోడల్‌కి పంపాలి (భారీగా డబ్బులు ఖర్చవుతాయి!).
- **కాంటెక్స్ట్ కాషింగ్:** ఆ 500 పేజీలను **ఒక్కసారే** గూగుల్ క్లౌడ్‌లో కాష్ చేస్తాం. ఆ తర్వాత ఉద్యోగులు ఎన్ని ప్రశ్నలు అడిగినా **75% తక్కువ ఖర్చు మరియు 3 రెట్లు ఎక్కువ వేగంతో** సమాధానాలు వస్తాయి!

## 6. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **ఫంక్షన్‌కి డాక్యుమెంటేషన్ (Docstring) రాయకపోవడం:**
   - AI కి మీ ఫంక్షన్ ఏం చేస్తుందో తెలియాలంటే దాని డాక్‌స్ట్రింగ్ మాత్రమే ఆధారం. `def query(x):` అని ఏమీ రాయకుండా వదిలేస్తే మోడల్ ఎప్పటికీ ఆ ఫంక్షన్‌ని సరిగ్గా పిలవలేదు.
2. **AI నే కోడ్ రన్ చేస్తుంది అనుకోవడం:**
   - AI కేవలం ఏ ఫంక్షన్ పిలవాలో మరియు ఏ ఆర్గుమెంట్స్ ఇవ్వాలో JSON రూపంలో చెబుతుంది. మీ పైథాన్ కోడ్ మాత్రమే ఆ ఫంక్షన్‌ని రన్ చేస్తుంది.
3. **భారీ 4K ఫోటోలను నేరుగా పంపడం:**
   - అనవసరమైన పెద్ద ఫోటోలు పంపితే ఎక్కువ టోకెన్లు ఖర్చవుతాయి. వాటి సైజును కాస్త తగ్గించి పంపడం ఉత్తమం.

## 7. ప్రాక్టీస్ ల్యాబ్ (Daily Hands-On Lab)

### 🧪 టాస్క్: ఫంక్షన్ కాలింగ్ ద్వారా పనిచేసే AI డేటాబేస్ అనలిస్ట్
**సన్నివేశం:** యూజర్ సాధారణ ఇంగ్లీషులో *"భారతదేశం నుండి వచ్చిన మొత్తం ఆదాయం ఎంత?"* అని అడుగుతాడు. AI స్వయంగా సరైన SQL క్వెరీని తయారు చేసి మన లోకల్ SQLite డేటాబేస్‌ను రన్ చేసి సమాధానం చెప్పాలి.

```python
# =========================================================
# Day 24 Lab: ఫంక్షన్ కాలింగ్ SQL అసిస్టెంట్
# =========================================================
import sqlite3
from google import genai
from google.genai import types

# 1. లోకల్ మెమొరీలో ఒక చిన్న SQLite డేటాబేస్ తయారు చేయడం
conn = sqlite3.connect(":memory:")
cursor = conn.cursor()
cursor.execute("CREATE TABLE sales (id INT, product TEXT, country TEXT, revenue_usd FLOAT)")
cursor.executemany("INSERT INTO sales VALUES (?, ?, ?, ?)", [
    (1, "Cloud AI License", "India", 4500.0),
    (2, "Developer Seat", "India", 1200.0),
    (3, "Enterprise Tier", "USA", 15000.0),
    (4, "Support Package", "UK", 3000.0)
])
conn.commit()

# 2. సురక్షితమైన పైథాన్ టూల్ (కేవలం SELECT క్వెరీలనే ఒప్పుకుంటుంది)
def execute_sql_query(query: str) -> str:
    """సేల్స్ డేటాబేస్ పై కేవలం రీడ్-ఓన్లీ SQL SELECT క్వెరీలను రన్ చేస్తుంది."""
    print(f"\n⚡ [టూల్ ఎగ్జిక్యూషన్] రన్ అవుతున్న SQL: {query}")
    if not query.strip().upper().startswith("SELECT"):
        return "ERROR: కేవలం SELECT క్వెరీలు మాత్రమే అనుమతించబడతాయి."
    try:
        cur = conn.cursor()
        cur.execute(query)
        rows = cur.fetchall()
        return str(rows)
    except Exception as e:
        return f"SQL లోపం: {e}"

# 3. జెమిని మోడల్‌తో ఫంక్షన్ కాలింగ్ రన్ చేయడం
client = genai.Client()
chat = client.chats.create(
    model="gemini-1.5-flash",
    config=types.GenerateContentConfig(
        system_instruction="నువ్వు ఒక బిజినెస్ అనలిస్ట్‌వి. 'sales' టేబుల్ నుండి సమాచారం తేవడానికి execute_sql_query టూల్‌ని వాడు.",
        tools=[execute_sql_query],
        temperature=0.0
    )
)

response = chat.send_message("భారతదేశంలోని కస్టమర్ల నుండి వచ్చిన మొత్తం ఆదాయం ఎంత?")
print("\n--- తుది AI బిజినెస్ రిపోర్ట్ ---")
print(response.text)
```

## 8. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: LLM లలో ఫంక్షన్ కాలింగ్ (Tool Calling) ఎలా పనిచేస్తుంది?**
   - **సమాధానం:** డెవలపర్ అందుబాటులో ఉన్న ఫంక్షన్ల వివరాలను JSON స్కీమా రూపంలో మోడల్‌కి ఇస్తాడు. యూజర్ ప్రశ్నను విశ్లేషించి, ఒక టూల్ అవసరమని మోడల్ గుర్తిస్తే, అది టెక్స్ట్ సమాధానం ఇవ్వకుండా ఆగిపోయి ఏ ఫంక్షన్ పిలవాలో మరియు ఏ పారామీటర్లు ఇవ్వాలో ఒక స్ట్రక్చర్డ్ కాల్‌ను రిటర్న్ చేస్తుంది. క్లయింట్ అప్లికేషన్ ఆ ఫంక్షన్‌ను రన్ చేసి ఫలితాన్ని మళ్లీ మోడల్‌కి ఇస్తుంది, దాని ఆధారంగా మోడల్ తుది సమాధానాన్ని రూపొందిస్తుంది.
2. **ప్రశ్న: మోడల్ నుండి 100% సరైన JSON అవుట్‌పుట్ పొందడం ఎలా సాధ్యమవుతుంది?**
   - **సమాధానం:** ఆధునిక LLM ఇంజిన్లు **Schema-Constrained Decoding (Grammar-based)** విధానాన్ని ఉపయోగిస్తాయి. Pydantic మోడల్ నుండి ఒక Finite State Machine ని నిర్మించి, టోకెన్ శాంప్లింగ్ సమయంలో JSON గ్రామర్‌ను ఉల్లంఘించే ఏ ఒక్క టోకెన్‌నూ మోడల్ ఎంచుకోకుండా నిరోధిస్తాయి.
3. **ప్రశ్న: కాంటెక్స్ట్ కాషింగ్ (Context Caching) అంటే ఏమిటి? ఎప్పుడు వాడాలి?**
   - **సమాధానం:** పెద్ద డాక్యుమెంట్లు లేదా కోడ్‌బేస్‌లను పదే పదే వాడినప్పుడు, వాటి Key-Value (KV) అటెన్షన్ స్టేట్స్‌ను GPU మెమొరీలో ముందే లెక్కించి భద్రపరచడాన్నే కాంటెక్స్ట్ కాషింగ్ అంటారు. దీనివల్ల తర్వాతి ప్రశ్నలప్పుడు మోడల్ మళ్లీ మొత్తం డాక్యుమెంట్‌ను చదవాల్సిన పనిలేకుండా, దాదాపు 80% వేగంగా మరియు 75% తక్కువ ఖర్చుతో సమాధానాలు ఇస్తుంది.
