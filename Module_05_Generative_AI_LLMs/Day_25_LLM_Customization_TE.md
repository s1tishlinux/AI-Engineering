## 2. ఫైన్-ట్యూనింగ్ డేటా ఫార్మాట్ (JSONL)

## 3. LoRA (Low-Rank Adaptation) అద్భుతం

ఒక 70 బిలియన్ పారామీటర్ల మోడల్‌లో 70,000,000,000 సంఖ్యలు (వెయిట్స్) ఉంటాయి.
- **ఫుల్ ఫైన్-ట్యూనింగ్ (పాత పద్ధతి):** మొత్తం 70 బిలియన్ వెయిట్స్‌ను మార్చాలి. దీనికి ₹80 లక్షల ఖరీదైన 8x A100 GPU సర్వర్లు కావాలి!
- **LoRA విప్లవం (2021):** అసలైన మోడల్ వెయిట్స్‌ను **పూర్తిగా ఫ్రీజ్ (లాక్)** చేస్తుంది. పక్కన కేవలం రెండు చిన్న లో-ర్యాంక్ మ్యాట్రిక్స్‌లను ($A$ మరియు $B$) మాత్రమే చేరుస్తుంది:

$$W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} (B \cdot A)$$

- మనం కేవలం **0.05% పారామీటర్లను మాత్రమే** ట్రైన్ చేస్తాం.
- ఆ చిన్న అడాప్టర్ సైజు డిస్క్ పై **కేవలం 50 MB లోపే** ఉంటుంది! దీనివల్ల ఒక సాధారణ గేమింగ్ ల్యాప్‌టాప్‌లో కూడా మోడల్‌ని ఫైన్-ట్యూన్ చేయవచ్చు.

## 4. క్వాంటైజేషన్ (Quantization - 140 GB నుండి 4 GB కి!)

డీప్ లెర్నింగ్‌లో వెయిట్స్‌ను సాధారణంగా 16-బిట్ ఫ్లోట్ (FP16) లో భద్రపరుస్తారు:
- 1 పారామీటర్ = 2 బైట్లు.
- 8 బిలియన్ పారామీటర్ల మోడల్‌ను నడపాలంటే $8 \times 2 = \mathbf{16\text{ GB}}$ గ్రాఫిక్స్ కార్డ్ (VRAM) కావాలి!

**క్వాంటైజేషన్** ఏం చేస్తుందంటే, ఖచ్చితత్వం తగ్గకుండా ఆ సంఖ్యలను 4-బిట్ పూర్ణ సంఖ్యలుగా (**INT4**) కుదిస్తుంది:
- 1 పారామీటర్ = 0.5 బైట్లు మాత్రమే.
- అదే 8 బిలియన్ మోడల్ సైజు **16 GB నుండి కేవలం 4.5 GB కి తగ్గిపోతుంది!** దాంతో అది మీ సాధారణ మ్యాక్‌బుక్ లేదా ల్యాప్‌టాప్‌లో రయ్యిమని పరిగెడుతుంది!

## 5. ఫ్రెషర్స్ చేసే సాధారణ తప్పులు (Common Pitfalls)

1. **కొత్త విషయాలు నేర్పడానికి ఫైన్-ట్యూనింగ్ చేయడం:**
   - ⚠️ **అత్యంత ఘోరమైన తప్పు:** కంపెనీ కొత్త డాక్యుమెంట్లు, వార్తలు మోడల్‌కి నేర్పడానికి ఫైన్-ట్యూనింగ్ చేయకూడదు! కొత్త సమాచారం కోసం **RAG** మాత్రమే వాడాలి. ఫైన్-ట్యూనింగ్ అనేది కేవలం భాషా శైలి, టోన్ మార్చడానికి మాత్రమే.
2. **క్యాటాస్ట్రోఫిక్ ఫర్గెట్టింగ్ (Catastrophic Forgetting):**
   - మోడల్‌కి కేవలం మెడికల్ కోడింగ్ మాత్రమే నేర్పిస్తే, అది తన పాత సాధారణ తెలివితేటలను మర్చిపోయే ప్రమాదం ఉంది.
3. **పాడైపోయిన డేటాతో ట్రైన్ చేయడం:**
   - మీ JSONL ఫైల్‌లో తప్పులుంటే, మోడల్ కూడా అదే తప్పులను బట్టీ పడుతుంది (**Garbage In, Garbage Out**).

## 6. ప్రాక్టీస్ ల్యాబ్ (Daily Hands-On Lab)

### 🧪 టాస్క్: LoRA మెమొరీ కాలిక్యులేటర్ & SFT డేటా వాలిడేటర్
**సన్నివేశం:** మీరు ఒక మోడల్‌ని ఫైన్-ట్యూన్ చేయడానికి సిద్ధమవుతున్నారు. LoRA వాడటం వల్ల ఎన్ని పారామీటర్లు మరియు ఎంత మెమొరీ ఆదా అవుతుందో లెక్కించే ఒక ఆటోమేటెడ్ కాలిక్యులేటర్‌ను తయారు చేయండి.

```python
# =========================================================
# Day 25 Lab: LoRA సామర్థ్య కాలిక్యులేటర్ & డేటా వాలిడేటర్
# =========================================================
import json

def calculate_lora_efficiency(hidden_dim: int = 4096, rank: int = 8, num_layers: int = 32):
    """LoRA ద్వారా ఆదా అయ్యే పారామీటర్లు మరియు మెమొరీని లెక్కిస్తుంది."""
    # సాధారణ ఫుల్ మోడల్ అటెన్షన్ వెయిట్స్
    full_params_per_layer = 2 * (hidden_dim * hidden_dim)
    total_full_params = full_params_per_layer * num_layers

    # LoRA అడాప్టర్ పారామీటర్లు (Matrix A: d x r, Matrix B: r x d)
    lora_params_per_layer = 2 * (hidden_dim * rank + rank * hidden_dim)
    total_lora_params = lora_params_per_layer * num_layers

    reduction_percentage = (1 - (total_lora_params / total_full_params)) * 100
    
    # FP16 మెమొరీ లెక్కలు (ఒక్కో పారామీటర్‌కి 2 బైట్లు)
    full_mem_mb = (total_full_params * 2) / (1024 * 1024)
    lora_mem_mb = (total_lora_params * 2) / (1024 * 1024)

    return {
        "ఫుల్ మోడల్ పారామీటర్లు": f"{total_full_params:,}",
        "LoRA అడాప్టర్ పారామీటర్లు": f"{total_lora_params:,}",
        "పారామీటర్ల ఆదా శాతం": f"{reduction_percentage:.2f}%",
        "ఫుల్ మోడల్ వెయిట్స్ సైజు": f"{full_mem_mb:.1f} MB",
        "LoRA అడాప్టర్ సైజు": f"{lora_mem_mb:.2f} MB"
    }

def validate_sft_dataset(sample_records: list[dict]) -> tuple[bool, list[str]]:
    """ChatML ప్రమాణాల ప్రకారం JSONL డేటా సరిగ్గా ఉందో లేదో తనిఖీ చేస్తుంది."""
    errors = []
    for idx, row in enumerate(sample_records):
        if "messages" not in row:
            errors.append(f"లైన్ {idx}: 'messages' కీ లేదు.")
            continue
        roles = [m.get("role") for m in row["messages"]]
        if "user" not in roles or "assistant" not in roles:
            errors.append(f"లైన్ {idx}: 'user' మరియు 'assistant' రెండూ ఉండాలి.")
    return len(errors) == 0, errors

# కాలిక్యులేటర్‌ను రన్ చేద్దాం:
lora_stats = calculate_lora_efficiency(hidden_dim=4096, rank=8, num_layers=32)

print("="*55)
print("LoRA PEFT సమర్థత నివేదిక")
print("="*55)
for k, v in lora_stats.items():
    print(f"{k:28}: {v}")
print("="*55)

# డేటాసెట్ వాలిడేషన్ టెస్ట్:
dummy_dataset = [
    {"messages": [{"role": "user", "content": "హలో"}, {"role": "assistant", "content": "నమస్కారం!"}]},
    {"broken_row": [{"role": "user", "content": "తప్పు ఫార్మాట్"}]}
]
is_valid, validation_errors = validate_sft_dataset(dummy_dataset)
print(f"\nడేటాసెట్ సరైనదేనా?: {is_valid} | గుర్తించిన తప్పులు: {validation_errors}")
```

## 7. ఇంటర్వ్యూలలో అడిగే ప్రశ్నలు (Interview Questions & Answers)

1. **ప్రశ్న: ఫైన్-ట్యూనింగ్ కంటే RAG ని ఎప్పుడు ఎంచుకోవాలి?**
   - **సమాధానం:** కంపెనీకి సంబంధించిన ప్రైవేట్ డాక్యుమెంట్లు, నిరంతరం మారే తాజా సమాచారం మరియు ఆధారాలతో కూడిన కచ్చితమైన సమాధానాలు (Citations) కావాల్సి వచ్చినప్పుడు **RAG** నే ఎంచుకోవాలి. మోడల్ యొక్క మాట్లాడే విధానం, టోన్ లేదా ప్రత్యేకమైన సింటాక్స్ నేర్పించాలనుకున్నప్పుడు మాత్రమే **ఫైన్-ట్యూనింగ్** వాడాలి.
2. **ప్రశ్న: LoRA ట్రైనింగ్ సమయంలో GPU మెమొరీని ఎలా ఆదా చేస్తుంది?**
   - **సమాధానం:** ఫుల్ ఫైన్-ట్యూనింగ్‌లో బిలియన్ల పారామీటర్ల వెయిట్స్, వాటి గ్రేడియంట్స్ మరియు ఆడమ్ (Adam) ఆప్టిమైజర్ స్టేట్స్ అన్నింటినీ GPU RAM లో మోయాలి. LoRA అసలైన వెయిట్స్‌ను ఫ్రీజ్ చేసి, చాలా చిన్న ర్యాంక్ ($r \ll d$) గల మ్యాట్రిక్స్‌లను మాత్రమే ట్రైన్ చేస్తుంది. దీనివల్ల ఆప్టిమైజర్ మెమొరీ 70% కంటే ఎక్కువగా ఆదా అయి, చిన్న కన్స్యూమర్ GPU లపై కూడా ట్రైన్ చేయవచ్చు.
3. **ప్రశ్న: LoRA మరియు QLoRA మధ్య తేడా ఏమిటి?**
   - **సమాధానం:** సాధారణ LoRA లో బేస్ మోడల్‌ను 16-బిట్ ఫ్లోట్ (FP16) లో లోడ్ చేసి 16-బిట్ అడాప్టర్లను జోడిస్తారు. **QLoRA** లో అసలైన బేస్ మోడల్‌ను **4-bit NormalFloat (NF4)** లోకి క్వాంటైజ్ చేసి మెమొరీని భారీగా తగ్గిస్తారు, కానీ గ్రేడియంట్లను 16-బిట్ LoRA అడాప్టర్లలోకి బ్యాక్‌ప్రాపగేట్ చేస్తారు; దీనివల్ల ఒకే ఒక్క 48GB GPU పై 70B మోడల్‌ను కూడా సులభంగా ఫైన్-ట్యూన్ చేయవచ్చు.
