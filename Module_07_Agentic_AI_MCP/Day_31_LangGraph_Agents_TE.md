## 1. ఈ రోజు మన గోల్స్ (Day 31 Learning Objectives)
- సాధారణ లీనియర్ చైన్స్ (Linear Chains) కంటే స్టేట్‌ఫుల్ గ్రాఫ్స్ (**LangGraph**) ప్రొడక్షన్ ఏజెంట్లలో ఎందుకు అవసరమో తెలుసుకోవడం.
- LangGraph లోని ముఖ్యమైన 4 పిల్లర్స్: **State (TypedDict/Pydantic)**, **Nodes (పైథాన్ ఫంక్షన్స్)**, **Edges (కండిషనల్ రూటింగ్)**, మరియు **Checkpointers (స్టేట్ సేవింగ్)**.
- **Human-in-the-Loop (HITL)** కాన్సెప్ట్: పెద్ద ప్రమాదకరమైన పనులు (డబ్బు బదిలీ, డేటా డిలీట్, ఈమెయిల్ పంపడం) చేసే ముందు ఏజెంట్ మనుషుల అనుమతి కోసం ఎలా ఆగాలో నేర్చుకోవడం.
- మల్టీ-ఏజెంట్ కోఆర్డినేషన్ (డెవలపర్, టెస్టర్, రివ్యూవర్ కలిసి ఎలా పనిచేస్తాయి).
- ఎర్రర్స్ వచ్చినప్పుడు సైక్లిక్ లూప్స్ (Cycles & Retries) ద్వారా సెల్ఫ్-కరెక్షన్ చేయడం.

## 2. రియల్ వరల్డ్ అనలాజీ (Real-World Analogy)

> 💡 **అనలాజీ: ఫ్యాక్టరీ కన్వేయర్ బెల్ట్ vs హాస్పిటల్ ఎమర్జెన్సీ వార్డ్**
>
> - **సాధారణ లీనియర్ చైన్ (Linear Chain):** ఒక ఫ్యాక్టరీ లో బాటిల్స్ నింపే కన్వేయర్ బెల్ట్ లాంటిది. స్టెప్ 1 లో బాటిల్ వస్తుంది -> స్టెప్ 2 లో వాటర్ పోస్తారు -> స్టెప్ 3 లో మూత పెడతారు. స్టెప్ 2 లో బాటిల్ పగిలిపోయినా, మిషన్ ఆగదు.. పగిలిన బాటిల్ పైనే మూత పెట్టి బయటకు తోస్తుంది. అంటే వెనక్కి వెళ్లి సరిదిద్దుకునే సదుపాయం ఉండదు.
> - **స్టేట్‌ఫుల్ గ్రాఫ్ (LangGraph):** ఇది ఒక పెద్ద హాస్పిటల్ లోని **ఎమర్జెన్సీ రూమ్ (ER)** లాంటిది!
>   - **State (స్టేట్):** పేషెంట్ మెడికల్ చార్ట్ (రక్తపోటు, జ్వరం, డాక్టర్ రాసిన ప్రిస్క్రిప్షన్). ఈ చార్ట్ అందరికీ షేర్ అవుతుంది.
>   - **ట్రయేజ్ నర్స్ (Node 1):** పేషెంట్ పరిస్థితిని చూసి, గుండె సమస్య అయితే వెంటనే **కార్డియాలజిస్ట్ (Node 2)** కి పంపిస్తుంది (Conditional Edge).
>   - **కార్డియాలజిస్ట్ (Node 2):** ఈసీజీ టెస్ట్ చూసి ఆపరేషన్ చేయాలని నిర్ణయిస్తాడు.
>   - **హ్యూమన్-ఇన్-ది-లూప్ (HITL Pause):** ఆపరేషన్ చేసే ముందు ఏజెంట్ ఆగి, *"పేషెంట్ అటెండర్ లేదా సీనియర్ డాక్టర్ సంతకం ఉంటేనే ముందుకు వెళ్తాను"* అని ఎగ్జిక్యూషన్ ని తాత్కాలికంగా ఆపుతుంది.
>   - సంతకం అవ్వగానే అక్కడినుండే తదుపరి పని మొదలవుతుంది!

## 3. LangGraph ఆర్కిటెక్చర్ ఫ్లో

```
                                 ┌──────────────┐
                                 │  START NODE  │
                                 └──────┬───────┘
                                        │
                                        ▼
                            ┌───────────────────────┐
                            │      Supervisor       │
                            │  (వర్క్ ప్లాన్ చేస్తుంది)│
                            └───────────┬───────────┘
                                        │
                         షరతులతో కూడిన మార్గం (Conditional Routing)

                        ▼                               ▼
             ┌─────────────────────┐         ┌─────────────────────┐
             │    Coder Agent      │         │   Researcher Agent  │
             │   (కోడ్ రాస్తుంది)  │         │  (సమాచారం వెతుకుతుంది)│
             └──────────┬──────────┘         └──────────┬──────────┘
                        │                               │
                        └───────────────┬───────────────┘
                                        ▼
                            ┌───────────────────────┐
                            │    Code Reviewer      │
                            │ (టెస్ట్ రన్ చేసి చూస్తుంది)│
                            └───────────┬───────────┘
                                        │
                         టెస్ట్ పాస్ అయిందా? (Check)
                      ┌─────────────────┴─────────────────┐
                      │ ఫెయిల్ (No)                        │ పాస్ (Yes)
                      ▼                                   ▼
          [మళ్ళీ Coder Node కి వెళ్ళు]           ┌─────────────────────┐
                                               │   HUMAN APPROVAL    │
                                               │   (మనిషి పర్మిషన్)   │
                                               └──────────┬──────────┘
                                                          │ Approved
                                                          ▼
                                               ┌─────────────────────┐
                                               │      END NODE       │
                                               │ (ప్రొడక్షన్ డిప్లాయ్) │
                                               └─────────────────────┘
```

## 4. LangGraph లోని ప్రధాన అంశాలు (Core Primitives)

1. **State (స్టేట్):** గ్రాఫ్ లోని అన్ని నోడ్స్ కి అందుబాటులో ఉండే షేర్డ్ మెమొరీ. దీనిని Python `TypedDict` లేదా `Pydantic` తో డిఫైన్ చేస్తాం.
2. **Nodes (నోడ్స్):** ఇవి సాధారణ పైథాన్ ఫంక్షన్స్. ఇవి ప్రస్తుత స్టేట్ ని ఇన్పుట్ గా తీసుకుని, ఏదైనా పని చేసి, మారిన విలువలను డిక్షనరీ గా రిటర్న్ చేస్తాయి.
3. **Edges (ఎడ్జెస్):** ఒక నోడ్ నుండి మరొక నోడ్ కి కంట్రోల్ ని నడిపించే దారులు.
   - *Normal Edge:* నోడ్ A ముగియగానే ఖచ్చితంగా నోడ్ B కి వెళ్తుంది.
   - *Conditional Edge:* స్టేట్ లోని వేరియబుల్స్ (ఉదా: `test_passed == True`) ని బట్టి ఏ నోడ్ కి వెళ్ళాలో ఒక రౌటర్ ఫంక్షన్ నిర్ణయిస్తుంది.
4. **Checkpointer & Interrupts:** గ్రాఫ్ ఏ క్షణంలో ఏ స్థితిలో ఉందో మెమొరీ లో లేదా డేటాబేస్ లో సేవ్ చేస్తుంది. దీనివల్ల మధ్యలో ఆగిపోయిన పనులను తిరిగి ప్రారంభించవచ్చు (Resume).

## 5. కోడింగ్ వాక్‌త్రూ: LangGraph & Human-in-the-Loop ప్రాక్టికల్ కోడ్

కింది ఉదాహరణలో డెవలపర్ రాసిన కోడ్ ని టెస్టర్ టెస్ట్ చేస్తుంది. తప్పు ఉంటే మళ్ళీ డెవలపర్ సరిదిద్దుతాడు. టెస్ట్ పాస్ అయ్యాక, ప్రొడక్షన్ కి వెళ్ళేముందు **Human Approval** కోసం గ్రాఫ్ ఆగుతుంది:

```python
import operator
from typing import Annotated, TypedDict, Literal, List
from langgraph.graph import StateGraph, END, START
from langgraph.checkpoint.memory import MemorySaver

# 1. స్టేట్ డిఫైన్ చేద్దాం
class AgentState(TypedDict):
    task: str
    code: str
    test_passed: bool
    iterations: int
    logs: Annotated[List[str], operator.add]  # లాగ్స్ ఓవర్‌రైట్ అవ్వకుండా లిస్ట్‌కి యాడ్ అవుతాయి

# 2. నోడ్ ఫంక్షన్స్
def developer_node(state: AgentState) -> dict:
    """కోడ్ రాసే లేదా ఫిక్స్ చేసే డెవలపర్ నోడ్."""
    iteration = state.get("iterations", 0) + 1
    
    if iteration == 1:
        # మొదటి ప్రయత్నం: బగ్ ఉన్న కోడ్
        code = "def multiply(a, b):\n    return a + b  # బగ్: గుణకారానికి బదులు కూడిక రాశారు"
        log = "డెవలపర్: మొదటి డ్రాఫ్ట్ కోడ్ రాశాను (బగ్ ఉంది)."
    else:
        # రెండవ ప్రయత్నం: సరైన కోడ్
        code = "def multiply(a, b):\n    return a * b  # బగ్ సరిదిద్దబడింది"
        log = "డెవలపర్: టెస్ట్ ఎర్రర్ చూసి కోడ్ ని సరిచేశాను."
        
    return {
        "code": code,
        "iterations": iteration,
        "logs": [log]
    }

def tester_node(state: AgentState) -> dict:
    """కోడ్ ని టెస్ట్ చేసే టెస్టర్ నోడ్."""
    code = state["code"]
    namespace = {}
    try:
        exec(code, namespace)
        multiply_fn = namespace["multiply"]
        assert multiply_fn(3, 4) == 12, "టెస్ట్ ఫెయిల్: multiply(3, 4) != 12"
        return {
            "test_passed": True,
            "logs": ["టెస్టర్: అన్ని యూనిట్ టెస్టులు విజయవంతంగా పాస్ అయ్యాయి ✅"]
        }
    except Exception as e:
        return {
            "test_passed": False,
            "logs": [f"టెస్టర్: యూనిట్ టెస్ట్ ఫెయిల్ అయింది ❌: {str(e)}"]
        }

def deploy_node(state: AgentState) -> dict:
    """ప్రొడక్షన్ లో డిప్లాయ్ చేసే నోడ్."""
    return {
        "logs": [f"డిప్లాయ్ ఇంజిన్: కోడ్ ప్రొడక్షన్ లో విజయవంతంగా డిప్లాయ్ చేయబడింది 🚀:\n{state['code']}"]
    }

# 3. కండిషనల్ రౌటింగ్ లాజిక్
def route_next_step(state: AgentState) -> Literal["developer", "human_approval", "__end__"]:
    if state["test_passed"]:
        return "human_approval"
    
    if state["iterations"] >= 3:
        return "__end__"  # 3 సార్లు ప్రయత్నించినా ఫెయిల్ అయితే ఆగిపోవాలి (Circuit Breaker)
        
    return "developer"  # మళ్ళీ ఫిక్స్ చేయడానికి డెవలపర్ వద్దకు వెళ్ళు

# 4. గ్రాఫ్ బిల్డ్ చేద్దాం
builder = StateGraph(AgentState)

builder.add_node("developer", developer_node)
builder.add_node("tester", tester_node)
builder.add_node("deploy", deploy_node)

builder.add_edge(START, "developer")
builder.add_edge("developer", "tester")

# కండిషనల్ ఎడ్జ్
builder.add_conditional_edges(
    "tester",
    route_next_step,
    {
        "developer": "developer",
        "human_approval": "deploy",  # డిప్లాయ్ కి వెళ్లే ముందు ఆగుతుంది
        "__end__": END
    }
)
builder.add_edge("deploy", END)

# 5. Checkpointer & Interrupt కాన్ఫిగరేషన్
memory = MemorySaver()
app = builder.compile(
    checkpointer=memory,
    interrupt_before=["deploy"]  # ⏸️ డిప్లాయ్ చేయడానికి ముందు ఖచ్చితంగా ఆగాలి!
)

# 6. రన్ చేద్దాం
if __name__ == "__main__":
    thread_config = {"configurable": {"thread_id": "session-dev-99"}}
    
    initial_input = {
        "task": "మల్టిప్లై ఫంక్షన్ రాయాలి",
        "code": "",
        "test_passed": False,
        "iterations": 0,
        "logs": ["ప్రాసెస్ ప్రారంభమైంది."]
    }
    
    print("\n--- దశ 1: హ్యూమన్ పర్మిషన్ వచ్చేంతవరకు గ్రాఫ్ రన్ అవుతుంది ---")
    for event in app.stream(initial_input, config=thread_config):
        for node, res in event.items():
            print(f"[{node}]: {res.get('logs', [''])[0]}")
            
    # ప్రస్తుత స్టేట్ పరిశీలన
    current_state = app.get_state(thread_config)
    print("\n⏸️ [గ్రాఫ్ ఆగిపోయింది (PAUSED)]")
    print(f"తదుపరి వేచి ఉన్న నోడ్: {current_state.next}")
    print(f"వెరిఫై చేయబడిన కోడ్:\n{current_state.values['code']}")
    
    # మనిషి ఆమోదం తెలిపినట్లు భావిద్దాం (Human Approval)
    print("\n--- దశ 2: మనిషి 'ఆమోదించాను (Approve)' అని క్లిక్ చేశారు ---")
    for event in app.stream(None, config=thread_config):
        for node, res in event.items():
            print(f"[{node}]: {res.get('logs', [''])[0]}")
```

## 6. ఫ్రెషర్స్ చేసే తప్పులు & పరిష్కారాలు

| సాధారణ తప్పు | ఎందుకు జరుగుతుంది? | నివారణ మార్గం |
| :--- | :--- | :--- |
| **లిస్ట్ లోని డేటా ఓవర్‌రైట్ అవ్వడం** | `logs: List[str]` అని సాధారణంగా రాస్తే, కొత్త నోడ్ రాసిన లాగ్ మాత్రమే మిగిలి పాతవన్నీ ఎగిరిపోతాయి. | ఎప్పుడూ `Annotated[List[str], operator.add]` రాయాలి. అప్పుడు పాత లిస్ట్‌కి కొత్త ఐటమ్స్ అపెండ్ అవుతాయి. |
| **ఇన్ఫినిట్ సైకిల్స్ (Infinite Loops)** | కండిషనల్ ఎడ్జ్ లో ఒకవేళ బగ్ ఫిక్స్ అవ్వకపోతే డెవలపర్-టెస్టర్ మధ్య నిరంతరం లూప్ అవుతూ బిల్లు పెరిగిపోతుంది. | స్టేట్ లో `iterations` లేదా `retry_count` వేరియబుల్ పెట్టి, 3 లేదా 5 సార్లు దాటితే `END` కి వెళ్ళేలా కండిషన్ పెట్టాలి. |
| **`thread_id` మర్చిపోవడం** | `app.get_state()` లేదా రెజ్యూమ్ చేసేటప్పుడు `thread_id` ఇవ్వకపోతే LangGraph ఏ యూజర్ సెషన్ గురించో అర్థం చేసుకోలేదు. | చెక్‌పాయింటర్ పనిచేయాలంటే తప్పకుండా `config={"configurable": {"thread_id": "xyz"}}` పాస్ చేయాలి. |

## 8. టాప్ 3 ఇంటర్వ్యూ ప్రశ్నలు & సమాధానాలు

### Q1: LangChain లోని పాత Chains కంటే LangGraph ఎందుకు మెరుగైనది?
**సమాధానం:**
LangChain లోని పాత చైన్స్ కేవలం ఒక వైపు మాత్రమే ప్రయాణిస్తాయి (A -> B -> C). మధ్యలో ఏదైనా తప్పు జరిగితే వెనక్కి వచ్చి లూప్ లో సరిదిద్దుకునే (Cycles / Retries) సదుపాయం వాటిలో లేదు. కానీ LangGraph లో మనం సైకిల్స్, కండిషనల్ రూటింగ్, మరియు ప్రతి దశలోనూ డేటాని సేవ్ చేసుకునే చెక్‌పాయింటింగ్ ఫీచర్లు పొందవచ్చు.

### Q2: LangGraph లో Human-in-the-Loop (HITL) ఎలా పనిచేస్తుంది?
**సమాధానం:**
గ్రాఫ్ ని కంపైల్ చేసేటప్పుడు `interrupt_before=["deploy_node"]` అని ఇస్తే, ఆ నిర్దిష్ట నోడ్ రన్ అవ్వడానికి ముందే ఎగ్జిక్యూషన్ ఆగిపోతుంది. అప్పటివరకు ఉన్న డేటా మొత్తం చెక్‌పాయింటర్ ద్వారా డేటాబేస్ లో సేవ్ అవుతుంది. మనిషి వెబ్ అప్లికేషన్ లో చెక్ చేసి ఆమోదం తెలిపినప్పుడు, `app.stream(None, config={"configurable": {"thread_id": "..."}})` అని పిలిస్తే గ్రాఫ్ అక్కడినుంచే యధావిధిగా ముందుకు సాగుతుంది.

### Q3: LangGraph లో State Reducers అంటే ఏమిటి?
**సమాధానం:**
సాధారణంగా ఒక నోడ్ ఏదైనా కీ ని రిటర్న్ చేస్తే, పాత విలువ స్థానంలో కొత్త విలువ రీప్లేస్ అవుతుంది. కానీ చాట్ మెసేజ్ లు లేదా యాక్షన్ లాగ్స్ లాంటివి పాత వాటికి కొత్తవి కలుపుకుంటూ వెళ్ళాలి (Append). దీనికోసం `Annotated[List[str], operator.add]` లేదా కస్టమ్ ఫంక్షన్ ద్వారా పాత స్టేట్ మరియు కొత్త స్టేట్ ఎలా విలీనం (Merge) కావాలో తెలిపే లాజిక్ నే Reducer అంటారు.
